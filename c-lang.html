🌟 Почему C?

C — компилируемый, статически типизированный, императивный, процедурный язык системного программирования. Создан Деннисом Ритчи в Bell Labs в 1972 году для разработки UNIX. Более 50 лет остаётся фундаментом всей вычислительной техники.

Используется в: Linux kernel, Windows kernel, macOS kernel (XNU), SQLite, Git, Redis, PostgreSQL, nginx, Python interpreter, PHP interpreter, Lua, Go runtime, Java JVM, embedded (ESP32, Arduino), драйверы, базы данных, компиляторы. Управление памятью — вручную, но полный контроль над железом.

01. Введение в C

История, философия, применение, стандарты языка, экосистема.

📖 Что такое C

C — компилируемый, статически типизированный, процедурный язык общего назначения. Создан Деннисом Ритчи в 1972 году в Bell Labs для переписывания UNIX с ассемблера. До этого — язык B (Кен Томпсон), ещё раньше — BCPL (Мартин Ричардс).

Ключевые особенности:

  • Низкоуровневый доступ к памяти — указатели, прямой доступ к железу
  • Минимальная стандартная библиотека — libc (~30 заголовочных файлов)
  • Отсутствие ООП — процедурный язык
  • Ручное управление памятью — malloc/free
  • Статическая типизация — но слабая (можно привести любой указатель к другому)
  • Компиляция в нативный код — максимальная производительность
  • Переносимость — стандарт ANSI C / ISO C работает везде
  • Undefined Behavior — много свободы, но легко выстрелить в ногу

Применение: ядра ОС (Linux, Windows, XNU), драйверы, embedded (ESP32, STM32, Arduino), компиляторы (GCC, Clang), базы данных (SQLite, PostgreSQL, Redis), интерпретаторы (Python, PHP, Ruby, Lua), сетевые стеки, криптография, embedded Linux, IoT.

03. Переменные и типы данных

int, char, float, double, sizeof, модификаторы, приведение типов.

📖 Теория

C — статически типизированный язык. Типы определяют размер и интерпретацию памяти.

Базовые типы:

  • char — 1 байт, символ (ASCII, иногда знаковый)
  • short — обычно 2 байта
  • int — обычно 4 байта
  • long — 4 или 8 байт (зависит от платформы — LP64/LLP64/ILP32)
  • long long — как минимум 8 байт
  • float — 4 байта, IEEE 754
  • double — 8 байт, IEEE 754
  • long double — 10/12/16 байт (зависит)
  • void — «ничего» (только для указателей/функций)

Модификаторы: signed, unsigned, short, long. Квалификаторы: const, volatile, restrict (C99).

Важно: размеры типов не фиксированы стандартом! Используйте <stdint.h> для фиксированных: int8_t, uint32_t, int64_t, и <stddef.h> для size_t.

⚠️ Переполнение signed — UB. Unsigned wraps around. Проверяйте границы!

04. Операторы и выражения

Арифметика, сравнение, логика, битовые, инкремент, тернарный.

📖 Теория

Арифметические: + - * / %. Деление целых — целочисленное. Остаток от отрицательных — знак делимого.

Инкремент/декремент: ++ --. Префиксный (сначала) и постфиксный (потом).

Сравнение: == != < > <= >=. Возвращают int (0 = false, !0 = true).

Логические: && || !. Короткое замыкание.

Битовые: & | ^ ~ << >>. Только для целых.

Присваивание: = += -= *= /= %= &= |= ^= <<= >>=.

Тернарный: cond ? a : b.

sizeof — оператор (не функция!), возвращает size_t.

Приоритеты: () — лучший друг. * и / выше + и -. && выше ||.

⚠️ i = i++ — UB! Не изменяйте переменную несколько раз в выражении.

05. Условия и switch

if/else, switch, тернарный, goto, switch fall-through.

📖 Теория

if/else — стандартное ветвление. Условие — int (0 = false, ненулевое = true).

switch — сравнение с целочисленными константами. Без break — fall-through (как в C++/Java).

switch (value) { case1: case2: // для 1 и 2break; case3: // только 3break; default: // остальноеbreak; }

Тернарный: cond ? a : b — выражение, возвращает значение.

goto — прыжок на метку. В C используется чаще, чем в C++: для выхода из вложенных циклов и cleanup при ошибках.

cleanup: free(buffer); return error;

Правила: никогда не забывайте break; используйте default; brace-инициализация { } рекомендуется; избегайте глубоких вложенных условий.

⚠️ if (x = 5) — классический баг! Используйте if (5 == x) (Yoda conditions) или -Wparentheses.

06. Циклы

for, while, do-while, break, continue, goto, вложенные.

📖 Теория

Три вида циклов:

  • for — классический, с инициализацией/условием/шагом
  • while — пока условие
  • do-while — хотя бы раз
for (int i = 0; i < 10; i++) { } while (condition) { } do { } while (condition);

break — выход, continue — следующая итерация. goto — прыжок на метку (для выхода из вложенных).

Важно: C не имеет range-based for (в отличие от C++/Java). Используйте for (int i = 0; i < n; i++) или while.

Бесконечные циклы: while (1) или for (;;) — стандартный паттерн.

⚠️ Классический баг: for (unsigned int i = 10; i >= 0; i--) — бесконечный цикл! i никогда не станет < 0.

Одномерные, многомерные, VLA, инициализация, отсутствие границ.

10. Указатели

*, &, NULL, арифметика, разыменование, массивы vs указатели.

📖 Теория

Указатель — переменная, хранящая адрес памяти. Главная особенность C и главный источник багов.

int x = 42; int* p = &x; // p хранит адрес xprintf("%d\n", *p); // 42 (разыменование) *p = 100; // изменение x через указатель

Основные операции:

  • & — взять адрес (address-of)
  • * — разыменовать (dereference)
  • NULL — нулевой указатель (проверяйте!)
  • Указатель на указатель: int** pp
  • Указатель на void: void* — универсальный, но нужен cast

Массивы и указатели: имя массива — указатель на первый элемент. arr[i] == *(arr + i).

⚠️ Типичные ошибки: разыменование NULL, дикий указатель (uninitialized), use-after-free, утечка памяти, выход за границы. Используйте -fsanitize=address и Valgrind!

12. Структуры и union

struct, union, padding, alignment, вложенные, указатели на структуры.

📖 Теория

struct — пользовательский тип, объединяющий несколько полей разных типов. В C нет методов — только данные.

struct Point { int x; int y; }; struct Point p = {1, 2}; p.x = 10; printf("%d\n", p.x);

Доступ: p.x (структура) или ptr->x (указатель на структуру).

typedef — псевдоним:

typedef struct { int x, y; } Point;

Padding и alignment — компилятор выравнивает поля, добавляя padding. sizeof(struct) может быть больше суммы полей!

struct Bad { char a; // 1 байт + 3 paddingint b; // 4 байтаchar c; // 1 байт + 3 padding }; // sizeof = 12, не 6!

union — все поля делят одну память. Размер = max из полей.

union Value { int i; float f; char bytes[4]; }; // sizeof = 4

Выравнивание: _Alignas(16) (C11), __attribute__((packed)) (GCC).

⚠️ Не сериализуйте структуру целиком — padding и порядок байтов (endianness) разные на разных платформах.

14. Управление памятью

malloc, calloc, realloc, free, утечки, double-free, Valgrind.

📖 Теория

C даёт полный контроль над памятью: stack (автоматическая), heap (ручная).

Функции кучи (<stdlib.h>):

  • malloc(size) — выделить size байт. Не инициализирует! Возвращает NULL при ошибке.
  • calloc(n, size) — выделить n × size, инициализировать нулями
  • realloc(ptr, new_size) — изменить размер (может переместить блок!)
  • free(ptr) — освободить. ptr должен быть из malloc/calloc/realloc или NULL

Правила:

  • Каждый malloc → ровно один free
  • Не free дважды (double-free — UB)
  • Не используйте после free (use-after-free)
  • Проверяйте NULL после malloc
  • free(NULL) — безопасно (no-op)
  • Не free стек/глобальные переменные
⚠️ Утечки памяти — самая частая проблема C. Каждый потерянный указатель = утечка. Используйте Valgrind, AddressSanitizer, LeakSanitizer!
💡 Правило: «кто выделил — тот и освобождает». Определяйте владение явно (документируйте).

15. Динамические массивы

Рост capacity, amortized O(1), реализация vector на C.

📖 Теория

C не имеет встроенного vector. Но его легко реализовать: struct + malloc + realloc.

Идея:

  • Хранить указатель на данные + size (использовано) + capacity (выделено)
  • При добавлении: если size == capacity — удвоить capacity через realloc
  • Amortized O(1) на push_back — потому что растём экспоненциально

Почему не растём по +1? — Тогда push_back был бы O(n), всего операций O(n²).

Growth factor: 1.5 (Java ArrayList) или 2 (C++ vector, Go slice). Компромисс: память vs скорость.

Связанные структуры: dynamic array — база для stack, queue, hash table.

💡 В C++ это std::vector, в Rust — Vec, в Go — slice. В C — пишите сами или берите stb_ds.h, klib, GLib GArray.

16. Связные списки

Singly, doubly, circular, операции, сравнение с массивами.

📖 Теория

Связный список — узлы в куче, связанные указателями. Каждый узел знает, где находится следующий.

struct Node { int value; struct Node* next; // singly }; struct DNode { int value; struct DNode* prev; struct DNode* next; // doubly };

Типы:

  • Singly linked — только вперёд. Меньше памяти, простой.
  • Doubly linked — и вперёд, и назад. Больше памяти, гибче.
  • Circular — последний указывает на первый. Для round-robin.

Операции:

  • prepend — O(1)
  • append — O(1) с tail-указателем, иначе O(n)
  • insert after — O(1) если есть узел
  • delete — O(1) если есть prev (или doubly)
  • find — O(n)

Плюсы: O(1) вставка/удаление при наличии узла; растёт без реаллокаций.

Минусы: cache-unfriendly (узлы разбросаны); overhead указателей; O(n) поиск.

⚠️ Классические баги: утечка узлов при удалении, dangling pointer, циклы (бесконечный обход), забыть обновить tail.

17. Файловый ввод/вывод

fopen, fclose, fread, fwrite, fgets, fprintf, бинарные файлы.

📖 Теория

Файлы в C — через FILE* (указатель на структуру). Две модели: текстовая и бинарная.

Режимы fopen:

  • "r" — чтение (файл должен существовать)
  • "w" — запись (перезаписывает)
  • "a" — дозапись (append)
  • "r+" — чтение+запись
  • "w+" — чтение+запись (перезапись)
  • "a+" — чтение+дозапись
  • "rb", "wb" — бинарный режим (важно на Windows)

Функции:

  • fopen / fclose — открыть/закрыть
  • fgetc / fputc — по символу
  • fgets / fputs — по строке
  • fscanf / fprintf — форматированный
  • fread / fwrite — блоки (бинарный)
  • fseek / ftell / rewind — позиционирование
  • feof / ferror — проверки
⚠️ Всегда закрывайте файлы — иначе утечка дескрипторов. Проверяйте возврат fopen на NULL!
💡 Используйте fopen_s (MSVC) или проверяйте errno для диагностики.

19. Битовые операции

& | ^ ~ << >>, маски, флаги, битовые поля, endianness.

📖 Теория

Битовые операции работают над отдельными битами — незаменимы в системном программировании (драйверы, embedded, сети, сжатие).

Операторы:

  • & — AND: 1 только если оба 1
  • | — OR: 1 если хотя бы один 1
  • ^ — XOR: 1 если различаются
  • ~ — NOT (инверсия всех бит)
  • << — сдвиг влево (умножение на 2)
  • >> — сдвиг вправо (деление на 2)

Идиомы:

// Установить бит x |= (1 << n); // Сбросить бит x &= ~(1 << n); // Переключить бит x ^= (1 << n); // Проверить битif (x & (1 << n)) { } // Младший установленный бит x & -x // Обнулить младший бит x & (x - 1) // Проверка на степень двойки (x & (x - 1)) == 0// Количество единиц (popcount) __builtin_popcount(x) // GCC/Clang

Битовые поля — экономия памяти в struct:

struct Flags { unsigned int a : 1; unsigned int b : 1; unsigned int c : 3; };
⚠️ Сдвиг на ширину типа или больше — UB. Сдвиг отрицательного числа влево — UB. Знаковый >> — implementation-defined.

20. Рекурсия

База, шаг, стек вызовов, хвостовая рекурсия, мемоизация.

📖 Теория

Рекурсия — функция вызывает саму себя. Нужны: базовый случай (иначе бесконечно) и шаг (приближение к базе).

intfactorial(int n) { if (n <= 1) return1; // базаreturn n * factorial(n - 1); // шаг }

Стек вызовов: каждый вызов = фрейм (аргументы, локалы, адрес возврата). Глубина рекурсии ограничена (обычно 8MB → ~100k вызовов).

Хвостовая рекурсия — рекурсивный вызов последний. GCC/Clang могут оптимизировать (TCO) в цикл, но C не гарантирует.

Мемоизация — кеширование результатов (для Фибоначчи, DP).

⚠️ Stack overflow — переполнение стека. Глубокую рекурсию заменяйте циклом или явным стеком.

Когда рекурсия хороша: деревья, графы, divide & conquer, парсинг, Ханой, перестановки.

Когда лучше цикл: линейные задачи, глубокая рекурсия, performance-critical код.

21. Структуры данных

Stack, queue, deque, hash table, tree basics, графы.

📖 Теория

Структуры данных — способы организации памяти. Выбор определяет сложность алгоритмов.

Стек (Stack) — LIFO (last in, first out). Функции: push, pop, peek. Применение: рекурсия, undo, парсинг выражений, DFS.

Очередь (Queue) — FIFO (first in, first out). Функции: enqueue, dequeue. Применение: BFS, обработка задач, буферы.

Дек (Deque) — с двух концов. Применение: sliding window, palindrome.

Хеш-таблица — O(1) доступ. Ключ → hash → bucket. Коллизии: chaining или open addressing.

Деревья: BST, AVL, Red-Black, B-tree. Применение: БД, файловые системы, компиляторы.

Куча (heap) — priority queue. Min-heap: родитель ≤ детей. Применение: Dijkstra, планировщики.

Графы: adjacency list/matrix. BFS, DFS, Dijkstra, Floyd-Warshall.

Big-O — асимптотическая сложность. O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n) < O(n!).

Сортировки:

  • Bubble — O(n²). Простая, неэффективная.
  • Selection — O(n²).
  • Insertion — O(n²), но хороша для почти отсортированных.
  • Merge — O(n log n), стабильная, требует O(n) памяти.
  • Quick — O(n log n) в среднем, O(n²) worst. In-place.
  • Heap — O(n log n), in-place.
  • Counting/Radix — O(n + k), для целых.

Поиск:

  • Linear — O(n). Для неотсортированных.
  • Binary — O(log n). Требует сортировки.
  • Hash — O(1) average. Для больших данных.

Divide & Conquer: разделить → решить → объединить. MergeSort, QuickSort, Binary Search, FFT.

Dynamic Programming: мемоизация + оптимальная подструктура. Fibonacci, knapsack, LCS.

Greedy: локально оптимальное = глобально оптимальное (иногда). Dijkstra, Huffman.

23. Многопоточность

pthreads, mutex, atomic, race condition, deadlock.

📖 Теория

C11 добавил <threads.h> (thrd_create и др.), но на практике почти везде используется POSIX threads (pthreads).

Основные функции:

  • pthread_create — создать поток
  • pthread_join — дождаться завершения
  • pthread_exit — завершить поток
  • pthread_mutex_lock / unlock — блокировка
  • pthread_cond_wait / signal — условные переменные
  • _Atomic (C11) — атомарные типы

Проблемы:

  • Race condition — результат зависит от порядка
  • Data race — одновременная запись без синхронизации = UB
  • Deadlock — взаимная блокировка
  • Livelock, starvation

Правила:

  • Всегда unlock после lock
  • Захватывайте мьютексы в одном порядке
  • Минимизируйте время под lock
  • Предпочитайте atomic для счётчиков
  • Компилируйте с -pthread
⚠️ В C нет GC, нет std::thread, нет RAII — управляйте мьютексами вручную. Ошибка = UB.

24. Сети и сокеты

TCP/UDP, socket API, сервер, клиент, HTTP-парсер.

📖 Теория

Сокет — endpoint для обмена данными. Основной API — BSD sockets (POSIX).

Типы:

  • SOCK_STREAM — TCP (надёжно, с установлением соединения)
  • SOCK_DGRAM — UDP (без соединения, быстрее)

Основные функции:

  • socket() — создать сокет
  • bind() — привязать к адресу/порту
  • listen() — сервер готов принимать
  • accept() — принять соединение
  • connect() — клиент соединяется
  • send/recv — отправка/приём
  • close() — закрыть

Порядок для сервера: socket → bind → listen → accept → recv/send → close

Порядок для клиента: socket → connect → send/recv → close

Структуры: sockaddr_in (IPv4), sockaddr_in6 (IPv6), addrinfo (современный).

⚠️ Не забывайте htons/htonl (network byte order — big-endian), close после работы, обработку ошибок.

26. Производительность

Кэш, SIMD, branch prediction, профилирование, inline, restrict.

📖 Теория

C — быстрый язык, но не «магически». Оптимизация требует измерений и понимания архитектуры.

Иерархия памяти (latency):

  • Регистры — < 1 ns
  • L1 кэш — ~1 ns, 32-64 KB
  • L2 кэш — ~10 ns, 256-512 KB
  • L3 кэш — ~50 ns, 4-32 MB
  • RAM — ~100 ns, GB
  • SSD — ~100 μs

Cache-friendly код:

  • Доступ к памяти последовательно (locality)
  • Struct of Arrays vs Array of Structs
  • Размер данных помещается в cache line (64 байт)

Компилятор:

  • -O0 — без оптимизации (для отладки)
  • -O1 — базовая
  • -O2 — стандартная (рекомендуется)
  • -O3 — агрессивная (векторизация, разворачивание)
  • -march=native — под текущий CPU
  • -flto — Link Time Optimization
  • -fprofile-generate / -fprofile-use — PGO (Profile-Guided Optimization)

Профилировщики: perf, gprof, Valgrind callgrind, Intel VTune, Google Performance Tools.

29. Системное программирование

Syscalls, POSIX, процессы, сигналы, embedded, ядро.

📖 Теория

C — главный язык системного программирования. Прямой доступ к syscalls, процессам, памяти, железу.

POSIX API (Linux/macOS/BSD):

  • Процессы: fork, exec, wait, exit
  • Сигналы: signal, sigaction, raise, kill
  • Файлы: open, read, write, close, lseek
  • Директории: opendir, readdir, closedir
  • IPC: pipe, fifo, shm, msg
  • Мьютексы: pthread_mutex

Системные вызовы — переход из user space в kernel space. Дорогие (100-1000 ns).

POSIX vs Win32: Linux/macOS — POSIX; Windows — Win32 API (CreateProcess, CreateFile).

Embedded: MCU (STM32, ESP32, AVR), bare metal (без ОС), RTOS (FreeRTOS).

Ядро Linux — ~30M строк C. Драйверы, файловые системы, планировщик.

⚠️ В системном коде особенно важны: обработка ошибок, атомарность, race conditions, утечки. Используйте strace, ltrace, perf.
