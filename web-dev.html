Частые вопросы

Чем фронтенд отличается от бэкенда?
Фронтенд выполняется в браузере пользователя: HTML, CSS и JavaScript отвечают за отображение и интерактивность. Бэкенд работает на сервере: обрабатывает запросы, хранит данные, проверяет права и возвращает результат. Обычно они общаются по HTTP или WebSocket.
Что такое SPA?
Single Page Application — одностраничное приложение, которое загружает HTML один раз, а дальше обновляет содержимое через JavaScript, без перезагрузки. Часто использует клиентский роутинг. Плюсы — быстрые переходы; минусы — сложнее SEO и первичная загрузка тяжелее.
Надо ли учить фреймворк?
Да, но после основ. Фундамент — HTML, CSS, JavaScript и понимание браузера — важнее конкретного фреймворка. Фреймворки меняются каждые несколько лет, а базовые знания остаются на десятилетия.

Раздел 02 / 30

История веба

Веб появился в CERN в конце 1980-х как средство обмена документами между учёными. За тридцать лет он превратился в платформу для приложений, развлечений, торговли и коммуникаций.

Рождение веба

В 1989 году Тим Бернерс-Ли предложил систему гипертекстовых документов, доступных по сети. Он же создал первые: язык разметки HTML, протокол HTTP, идентификаторы URL и первый браузер.

В 1993 году CERN открыл технологию для свободного использования — и веб начал распространяться взрывными темпами.

Войны браузеров

Netscape и Microsoft Internet Explorer боролись за пользователей, вводя несовместимые расширения HTML и JavaScript. Это замедлило стандартизацию, но подтолкнуло к созданию W3C и WHATWG.

Победа Chrome в конце 2000-х и появление V8 (JIT-компилятора) ускорили JavaScript в разы, открыв дорогу современным SPA.

HTML — структура

HTML (HyperText Markup Language) — это язык разметки, описывающий структуру и семантику документа. Каждый тег рассказывает браузеру и поисковикам, что именно представляет элемент.

Вместо безликих <div> используйте <header>, <nav>, <main>, <article>, <aside>, <section>, <footer>. Это улучшает SEO, доступность и читаемость.

FAQ

Почему <div> всё ещё используется?
<div> — универсальный контейнер без семантики. Его применяют, когда нужен структурный блок без смысловой роли (например, обёртка для стилизации). Если у блока есть смысл — лучше использовать семантические теги.
Что такое атрибуты data-*?
Атрибуты data-* позволяют хранить произвольные данные в HTML и легко читать их из JavaScript через element.dataset. Это удобно для небольших настроек без классов и id.
Зачем нужен DOCTYPE?
Он сообщает браузеру, что документ написан по современному стандарту HTML5. Без DOCTYPE браузер может включить «quirks mode» с нестандартным поведением CSS.

CSS — стилизация

CSS (Cascading Style Sheets) — язык, описывающий внешний вид HTML. Он отделяет содержимое от оформления, позволяет создавать раскладки, анимации, адаптивные интерфейсы и поддерживать темы.

Каскад и специфичность

Стили применяются в порядке каскада: сначала браузерные, затем авторские, затем !important. При равенстве побеждает более специфичное правило, затем — более позднее.

Интерактив · Блочная модель (box model)

Каждый элемент — это прямоугольник с content, padding, border и margin. box-sizing: border-box учитывает padding и border в заданной ширине.

Селекторы

Тег, класс, id, атрибуты, псевдоклассы :hover, :focus, псевдоэлементы ::before, ::after. Комбинации: .a .b, .a > .b, .a + .b.

Переменные

CSS-переменные (--name) позволяют хранить значения и переиспользовать их. Отлично работают для тем и цветов бренда.

Раздел 07 / 30

Асинхронность и Promise

Асинхронность позволяет не блокировать интерфейс во время долгих операций: запросов, таймеров, чтения файлов. Промисы и async/await — современный способ работы с такими операциями.

Промисы

const p = new Promise((resolve, reject) => {
  setTimeout(() => {
    const ok = Math.random() > 0.5;
    ok ? resolve('готово') : reject(new Error('ошибка'));
  }, 1000);
});

p.then(v => console.log(v))
 .catch(e => console.error(e))
 .finally(() => console.log('конец'));

async/await

async function load() {
  try {
    const res = await fetch('/api/data');
    const data = await res.json();
    return data;
  } catch (e) {
    console.error(e);
  }
}
Интерактив · Таймлайн промиса

Промис начинается в состоянии pending, затем переходит в fulfilled или rejected. Колбэки выполняются в микротаски — после текущего синхронного кода.

PromiseЦепочки, единый catchМного .then
async/awaitЧитается как синхронный кодНужен try/catch, топ-левел await не везде
Observables (RxJS)Стримы, мощные операторыКрутая кривая обучения

FAQ

Чем микротаски отличаются от макротасок?
Микротаски (промисы, queueMicrotask) выполняются после каждой макротаски и перед рендерингом. Макротаски — таймеры и события. Поэтому .then срабатывает раньше setTimeout(0).
Что делает Promise.all?
Запускает промисы параллельно и ждёт завершения всех. Если хотя бы один отклонится — Promise.all отклонится тоже. Есть Promise.allSettled (все результаты) и Promise.race (первый завершившийся).
Что такое unhandled rejection?
Если промис отклонён, но нет обработчика ошибки, браузер может сообщить об этом. В Node.js это приводит к падению процесса. Всегда добавляйте catch или try/catch вокруг await.

Grid и Flexbox

Два современных инструмента раскладки. Flexbox — для одномерных потоков (строка или колонка). Grid — для двумерной сетки. Вместе они закрывают почти все задачи вёрстки.

Flexbox

.row {
  display: flex;
  gap: 16px;
  align-items: center;
  justify-content: space-between;
  flex-wrap: wrap;
}
.row > * {
  flex: 1 1 200px;
}

Grid

.cards {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(240px, 1fr));
  gap: 16px;
}
Интерактив · Раскладка

Переключите режим — увидите, как по-разному ведут себя Flexbox и Grid. Flexbox управляет одним направлением, Grid — двумя.

Анимации и переходы

Анимации делают интерфейс живым и понятным. Но анимация ради анимации — плохо: она должна направлять внимание и объяснять изменение состояния, не мешая работе.

Transition

.btn {
  background: #00d4ff;
  transition: transform .2s ease, background .3s;
}
.btn:hover {
  background: #ff3b9d;
  transform: translateY(-2px);
}

Keyframes

@keyframes pulse {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.1); }
  100% { transform: scale(1); }
}
.badge {
  animation: pulse 1.6s ease-in-out infinite;
}
Интерактив · Easing-функции

Кривая easing задаёт скорость изменения во времени. Линейная — монотонная, ease-in-out — плавная, cubic-bezier — любая.

Рекомендации

  • Анимируйте transform и opacity — они дешёвые для браузера.
  • Избегайте анимации width, height, top, left — они вызывают reflow.
  • Уважайте prefers-reduced-motion.
  • Держите анимации короткими: 150–300 мс для UI, до 1 с для больших переходов.
  • Не анимируйте больше 2–3 свойств одновременно.

SVG и Canvas

Для векторной и растровой графики в вебе есть два основных инструмента. SVG удобен для иконок и схем, Canvas — для больших сцен и игр.

SVG: пример

<svg viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40"
          fill="#00d4ff" stroke="#ff3b9d"
          stroke-width="4"/>
  <path d="M20,80 Q50,20 80,80"
        stroke="#7cff9d" fill="none"/>
</svg>

Canvas: пример

const canvas = document.querySelector('canvas');
const ctx = canvas.getContext('2d');
ctx.fillStyle = '#00d4ff';
ctx.beginPath();
ctx.arc(50, 50, 40, 0, Math.PI * 2);
ctx.fill();
Интерактив · Рисование пути SVG

Путь строится из команд: M (move), L (line), Q (quadratic), C (cubic), A (arc). SVG масштабируется без потерь.

FAQ

Когда Canvas лучше SVG?
Когда на сцене тысячи объектов или идёт непрерывная анимация: каждый SVG-узел — отдельный DOM-элемент со своими стилями. Canvas перерисовывает всё в одном полотне.
Что такое viewBox?
Система координат SVG. viewBox="0 0 100 100" означает, что внутренние координаты идут от 0 до 100. Это позволяет масштабировать графику без потери качества.
Что такое devicePixelRatio?
Отношение физических пикселей к CSS-пикселям. На Retina-экранах оно равно 2 или 3. Для чёткого Canvas нужно увеличивать его внутренние размеры в соответствии с DPR.

Изображение на экране — это сетка пикселей. На Retina-экранах плотность выше, поэтому нужны источники большего размера или вектор.

Практики оптимизации

  • Задавайте width и height, чтобы избежать сдвигов верстки (CLS).
  • Сжимайте изображения без видимой потери качества.
  • Применяйте loading="lazy" для изображений ниже первого экрана.
  • Не забудьте про alt — это важно для доступности.
  • Для иконок используйте SVG-спрайты или инлайн SVG.

Медиаэлементы HTML5 позволяют воспроизводить аудио и видео без плагинов. Субтитры, постеры, форматы и автоплей — всё это управляется через атрибуты и API.

FAQ

Можно ли хранить токены в localStorage?

Базы данных

База данных — сердце любого приложения. Реляционные СУБД работают со строгими схемами, документные и ключ-значение — гибче. Выбор зависит от задачи и профиля нагрузки.

SQL-пример

CREATE TABLE users (
  id    SERIAL PRIMARY KEY,
  name  TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL
);

SELECT u.name, COUNT(p.id) AS posts
FROM users u
LEFT JOIN posts p ON p.user_id = u.id
GROUP BY u.id
ORDER BY posts DESC;

Индексы

CREATE INDEX idx_users_email
ON users(email);

Индексы ускоряют поиск и сортировку, но замедляют вставку и занимают место. Индексируйте поля в WHERE, JOIN, ORDER BY.

Интерактив · Таблицы и связи

Реляционная база — это таблицы со связями. Внешние ключи обеспечивают целостность, а JOIN'ы собирают данные из разных таблиц.

Аутентификация и безопасность

Аутентификация проверяет, кто вы. Авторизация — что вам разрешено. Современные приложения используют сессии, JWT или OAuth/OIDC.

Сессии и cookie

Set-Cookie: sid=abc123;
            HttpOnly;
            Secure;
            SameSite=Lax;
            Path=/

Сервер хранит сессию, клиент присылает идентификатор. Флаги HttpOnly и Secure защищают cookie от XSS и перехвата.

JWT

header.payload.signature

Токен содержит claim'ы и подпись. Сервер проверяет подпись, но не отозвать токен до истечения срока. Используйте короткоживущие access-токены + refresh-токены.

Интерактив · Проверка токена

Сервер сверяет подпись токена с секретом. Если подпись корректна и срок не истёк — доступ разрешён.

Сравнение подходов

ПодходПлюсыМинусы
Сессии + cookieЛегко отозвать, безопасно при HttpOnlyНужно хранилище сессий
JWTStateless, удобно для APIСложно отзывать, размер
OAuth / OIDCСтандарт для SSO и внешних провайдеровСложнее в реализации
API-ключиПросто для серверных интеграцийНе для пользователей

Частые уязвимости

XSS

Внедрение скриптов в страницу. Защита: экранирование, CSP, HttpOnly cookies.

CSRF

Запрос от имени пользователя без его ведома. Защита: SameSite cookies, CSRF-токены.

SQL-инъекции

Подстановка SQL через ввод. Защита: параметризованные запросы и ORM.

FAQ

Где хранить JWT?
В памяти (лучше всего для защиты от XSS) или в HttpOnly cookie (защита от JS-доступа, но нужна защита от CSRF). Не храните долгоживущие токены в localStorage — это уязвимо к XSS.
Что такое bcrypt?
Алгоритм хэширования паролей с солью и растущей сложностью. Храните только хэш, а не сам пароль. Для проверки используйте bcrypt.compare.
Что такое Content Security Policy?
Заголовок CSP ограничивает, откуда можно загружать скрипты, стили, картинки и т.д. Это мощная защита от XSS, если настроена строго.

Тестирование

Тесты — страховка от регрессий. Хорошая пирамида тестирования включает юнит-тесты, интеграционные и end-to-end. Автоматизация экономит часы ручной проверки.

Юнит-тест (Jest)

function sum(a, b) { return a + b; }

test('складывает числа', () => {
  expect(sum(2, 3)).toBe(5);
  expect(sum(-1, 1)).toBe(0);
});

E2E-тест (Playwright)

const { test, expect } = require('@playwright/test');

test('логин', async ({ page }) => {
  await page.goto('/login');
  await page.fill('#email', 'user@example.com');
  await page.fill('#pass', 'secret');
  await page.click('button[type=submit]');
  await expect(page).toHaveURL('/dashboard');
});
Интерактив · Пирамида тестов

Больше всего должно быть юнит-тестов (быстрые), меньше — интеграционных, ещё меньше — end-to-end (медленные, но самые близкие к реальности).

Практики

  • Тесты должны быть быстрыми и изолированными.
  • Не тестируйте чужой код (фреймворк, библиотеки).
  • Используйте фабрики и фикстуры вместо дублирования данных.

Git — распределённая система контроля версий. Она хранит историю изменений, позволяет работать параллельно в ветках и безопасно экспериментировать.

Базовый цикл

git init
git add .
git commit -m "первый коммит"
git branch feature
git checkout feature

Работа в команде

git pull origin main

Перед пушем подтяните изменения и разрешите конфликты. Rebase делает историю линейной, но переписывает коммиты.

PWA и Service Workers

Progressive Web App — веб-приложение, которое ведёт себя как нативное: устанавливается, работает офлайн, получает push-уведомления. Основа — Service Worker и Web App Manifest.

Регистрация SW

if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js');
}

Кэш в SW

self.addEventListener('install', (e) => {
  e.waitUntil(
    caches.open('v1').then(c =>
      c.addAll(['/', '/style.css', '/app.js'])
    )
  );
});
Интерактив · Офлайн-режим

Service Worker перехватывает запросы. Если ресурс в кэше — отдаёт из кэша, если нет — идёт в сеть. Так работает офлайн.

PWA и Service Workers: разбор на практике

PWA использует возможности веб-платформы для установки и работы при нестабильной сети. Service Worker может управлять кэшем, но стратегия обновления должна предотвращать ситуацию, когда старая оболочка использует несовместимые новые файлы.

Бинарный формат для высокопроизводительного кода. Позволяет запускать C/C++/Rust в браузере со скоростью, близкой к нативной. Используется в играх, редакторах, криптографии, AI.

🎮

Современный низкоуровневый API для GPU. Заменяет WebGL, даёт доступ к compute-шейдерам. Открывает путь для ML-инференса, 3D-рендеринга и физики.

🌐

Код выполняется ближе к пользователю на CDN-пограничных серверах. Меньше задержки, персонализация, edge-функции в Next.js, Cloudflare Workers.

🧠

Встроенные модели и трансформеры в браузере. WebNN, WebGPU-инференс, prompt-API. Приватность + скорость.

🎨

CSS-новинки

🔐

Passkeys
