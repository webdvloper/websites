01. Введение в HTML и CSS

История, стандарты W3C, как браузер рендерит страницу, что такое вёрстка.

📖 Что такое HTML

HTML (HyperText Markup Language) — язык разметки, который описывает структуру веб-страницы. Создан Тимом Бернерсом-Ли в 1991 году в CERN. HTML — не язык программирования (нет переменных, циклов), а язык разметки: он помечает, что есть что.

HTML описывает семантику: этот блок — заголовок, это — параграф, это — ссылка. Браузеры читают HTML и строят из него DOM-дерево, которое затем отображают на экране.

Стандарт HTML развивается под эгидой WHATWG (Living Standard). Текущая версия — HTML5, хотя формально это «живой стандарт», постоянно обновляемый.

📖 Что такое CSS

CSS (Cascading Style Sheets) — язык описания внешнего вида документа. Создан Хоконом Виум Ли в 1994 году, стандартизирован W3C в 1996-м.

CSS отделяет представление от структуры: HTML отвечает за «что», CSS — за «как выглядит». До CSS стили задавались прямо в HTML-тегах (<font color="red">) — это было кошмаром поддержки.

Современный CSS — это мощная система: Flexbox, Grid, анимации, переменные, container queries, вложенность. CSS3 разбит на модули, которые развиваются независимо.

🧭 Практический кейс: первая страница

Создайте файл index.html с минимальной структурой и откройте в браузере.

<!DOCTYPE html> <html lang="ru"> <head> <meta charset="UTF-8"> <title>Моя страница</title> </head> <body> <h1>Привет, мир!</h1> </body> </html>

Каждая часть обязательна: doctype сообщает браузеру стандарт, lang="ru" помогает скринридерам и поиску, charset отвечает за кириллицу.

02. Структура HTML-документа

doctype, html, head, body, как браузер читает документ.

📖 Скелет документа

Любой HTML-документ начинается с <!DOCTYPE html> — инструкции, что это HTML5. Затем идёт корневой тег <html>, внутри которого два основных контейнера:

  • <head> — метаданные: кодировка, заголовок страницы, подключение CSS, favicon, meta-теги. Не отображается на странице.
  • <body> — видимое содержимое: текст, изображения, ссылки, формы.

Внутри head обязательны: <meta charset> (кодировка), <title> (заголовок вкладки), <meta name="viewport"> (адаптивность на мобильных).

🧭 Практический кейс: что случится без viewport?

Без meta name="viewport" мобильные браузеры показывают страницу «как на десктопе» — всё будет мелким и придётся зумить. Всегда добавляйте его.

<meta name="viewport" content="width=device-width, initial-scale=1.0">

03. Теги и атрибуты

Парные теги, self-closing, глобальные атрибуты, class, id, data-*.

📖 Что такое тег

Тег — единица разметки в угловых скобках. Бывает:

  • Парный — открывающий и закрывающий: <p>...</p>, <div>...</div>.
  • Одиночный (self-closing) — без содержимого: <img>, <br>, <input>, <hr>.

Атрибут — дополнительная информация в открывающем теге: <a href="...">. Формат: имя="значение".

Глобальные атрибуты доступны любому тегу: class, id, style, title, hidden, tabindex, data-*, lang, dir.

🧭 Практический кейс: class vs id

05. Ссылки и изображения

📖 Ссылки

  • Скачивание: download

Современные атрибуты: width/height (задают пропорции — предотвращают layout shift), loading="lazy" (ленивая загрузка), srcset + sizes (адаптивные изображения).

<figure> + <figcaption> — для изображений с подписью.

12. Каскад и специфичность

Специфичность, !important, наследование, порядок.

📖 Теория

Каскад — правило, по которому браузер решает, какое свойство применить, когда на элемент действует несколько правил.

Специфичность считается по 4 категориям (a, b, c, d):

  • a — inline-стили (style="...")
  • b — id
  • c — классы, атрибуты, псевдоклассы
  • d — теги, псевдоэлементы

Примеры:

p → 0,0,0,1 .card → 0,0,1,0 .card .title → 0,0,2,0 #header → 0,1,0,0 #header .nav a → 0,1,1,1 inline style → 1,0,0,0 !important → побеждает всё (кроме другого !important)

!important — использовать максимально редко. Если он «нужен» часто — это признак плохой архитектуры стилей.

Наследование — некоторые свойства (color, font, line-height) переходят к потомкам. Другие (margin, padding, border) — нет.

19. Позиционирование

static, relative, absolute, fixed, sticky, top/left/z-index.

📖 Теория

  • static — по умолчанию. Элемент в потоке, top/left не работают.
  • relative — смещение относительно своего места. Поток сохраняется.
  • absolute — вырывается из потока. Позиционируется относительно ближайшего позиционированного предка.
  • fixed — вырывается из потока. Позиционируется относительно окна, не двигается при скролле.
  • sticky — гибрид: ведёт себя как relative, пока не достигнет края, потом как fixed.

top/right/bottom/left работают для всех кроме static. z-index — порядок наложения (работает только для позиционированных).

25. Container queries и современный CSS

📖 Теория

Container queries — новый стандарт: стили зависят не от размера окна, а от размера контейнера. Идеально для компонентов, которые используются в разных местах.

.card-container { container-type: inline-size; } @container (min-width: 400px) { .card { flex-direction: row; } }

:has() — родительский селектор: «элемент, у которого есть…».

:is() — группировка: :is(h1, h2, h3).

:where() — как :is, но с нулевой специфичностью.

Вложенный CSS — нативный, без Sass:

.card { padding: 16px; & .title { font-size: 1.2rem; } &:hover { background: #eee; } }

27. Z-index и stacking context

Слои, контексты наложения, position, opacity, transform.

📖 Теория

z-index — порядок наложения элементов по оси Z. Работает только для позиционированных элементов (position ≠ static) или flex/grid-элементов.

Stacking context — «плоскость», внутри которой работают свои z-index. Новый контекст создаётся при:

  • position: relative/absolute/fixed/sticky + z-index ≠ auto
  • opacity < 1
  • transform, filter, perspective
  • will-change с transform/filter
  • isolation: isolate
  • flex/grid child с z-index ≠ auto
  • contain: layout/paint

Ловушка: если родитель создал stacking context с маленьким z-index, дочерний z-index:9999 всё равно будет под соседом с z-index:1.
