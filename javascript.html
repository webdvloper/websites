01. Введение в JavaScript

История, экосистема, движки, среда выполнения, первая программа.

📖 Что такое JavaScript

JavaScript (JS) — мультипарадигменный язык программирования, изначально созданный для браузеров. Сегодня работает и на сервере (Node.js, Deno, Bun), в мобильных приложениях (React Native), десктопе (Electron).

Создан Бренданом Айком за 10 дней в мае 1995 года в Netscape. Изначально назывался Mocha, потом LiveScript, потом JavaScript (маркетинговый ход — Java была популярна). Официальное название стандарта — ECMAScript.

Ключевые особенности:

  • Динамическая типизация — тип определяется во время выполнения
  • Функции первого класса — функции можно присваивать, передавать, возвращать
  • Прототипное наследование — вместо классов (до ES6) были прототипы
  • Однопоточная модель с event loop и асинхронностью
  • JIT-компиляция — движки (V8, SpiderMonkey) компилируют в машинный код

Основные движки: V8 (Chrome, Node.js), SpiderMonkey (Firefox), JavaScriptCore (Safari), Chakra (старый Edge).

02. Переменные: let, const, var

Объявление, области видимости, hoisting, TDZ, когда что использовать.

📖 Теория

В JavaScript три способа объявить переменную: var (старый), let и const (ES6+).

  • var — функциональная область видимости, поднимается (hoisting) в начало функции, можно переопределять
  • let — блочная область видимости ({ }), поднимается но в TDZ, можно переопределять
  • const — блочная, поднимается в TDZ, нельзя переопределять (но содержимое объектов/массивов менять можно)

TDZ (Temporal Dead Zone) — «временная мёртвая зона». Между началом блока и объявлением let/const переменная существует, но обращение к ней бросает ReferenceError.

Рекомендация: по умолчанию const. Если нужно переопределять — let. var — никогда (только для legacy-кода).

03. Типы данных

7 примитивов + объект, typeof, приведение типов, NaN.

📖 Теория

В JavaScript 7 примитивных типов и объект:

  • number — 64-битное IEEE 754 (int и float вместе)
  • string — строки Unicode (неизменяемые)
  • boolean — true / false
  • null — намеренное отсутствие значения
  • undefined — значение не задано
  • symbol — уникальный идентификатор (ES6)

04. Операторы

Арифметические, сравнения, логические, == vs ===, нулевое слияние.

📖 Теория

Операторы делятся на группы:

  • Арифметические: + − * / % ** ++ --
  • Сравнения: == != === !== < > <= >=
  • Логические: && || ! ??
  • Присваивания: = += -= *= /= **= %= &&= ||= ??=
  • Тернарный: cond ? a : b
  • Опциональная цепочка: obj?.prop
  • Spread/rest: ...

== vs ===: == (нестрогое) приводит типы, === (строгое) — нет. Правило: всегда используйте ===, кроме случая x == null (проверка null ИЛИ undefined).

?? (nullish coalescing) возвращает правый операнд только если левый null или undefined. Отличается от ||, который срабатывает на любое falsy (0, "", false).

?. (optional chaining) — безопасный доступ: obj?.prop?.nested вернёт undefined вместо TypeError.

05. Условия и switch

if / else if / else, switch, тернарный оператор, truthy/falsy.

📖 Теория

if/else if/else — базовое ветвление. Условие приводится к boolean: 0, "", null, undefined, NaN, false — ложны, всё остальное — истинно.

switch — сравнение с несколькими значениями через ===. Важно не забывать break, иначе «провал» (fallthrough) — иногда это фича, но чаще баг.

Логическое присваивание — a = a || b можно короче: a ||= b.

06. Циклы

for, while, do-while, for-of, for-in, break, continue, labels.

📖 Теория

Виды циклов:

  • for (init; cond; step) — классический, когда известно количество итераций
  • while (cond) — пока условие истинно
  • do ... while (cond) — выполнится хотя бы раз
  • for ... of — по итерируемым объектам (array, string, Map, Set)
  • for ... in — по ключам объекта (не используйте для массивов!)

break — выход из цикла, continue — переход к следующей итерации, labels — прервать внешний цикл.

Array methods (forEach, map, filter) — часто лучше, чем циклы: короче и выразительнее. Но для ранних выходов иногда нужен for или for-of + break.

08. Стрелочные функции и this

Лексический this, call/apply/bind, когда arrow нельзя использовать.

📖 Теория

this — ключевое слово, ссылающееся на контекст вызова. Значение зависит от того, как вызвана функция:

  • Метод объекта: obj.foo() → this = obj
  • Обычная функция: foo() → this = undefined (strict) / window (sloppy)
  • Конструктор: new Foo() → this = новый объект
  • call/apply/bind — явно задать this

Стрелочные функции НЕ имеют своего this — они берут его из окружающей области (лексически). Это удобно в колбэках, но ломается при использовании как методов объекта.

call(thisArg, ...args) — вызвать с явным this. apply(thisArg, argsArray) — то же, но массивом. bind(thisArg) — вернуть функцию с привязанным this.

09. Замыкания и scope

Лексическая область видимости, замыкания, IIFE, утечки памяти.

📖 Теория

Scope — область видимости переменных. В JS три вида:

  • Global — глобальная
  • Function — внутри функции (var)
  • Block — внутри { } (let, const)

Лексический scope — область видимости определяется местом объявления в коде, а не местом вызова.

Замыкание (closure) — функция, «запоминающая» переменные из внешнего scope, даже после завершения внешней функции.

IIFE (Immediately Invoked Function Expression) — (function(){})() — немедленно вызываемая функция. Раньше использовалась для изоляции scope.

Замыкания — основа модулей, декораторов, счётчиков, мемоизации. Но они могут держать ссылки на переменные и вызывать утечки памяти.

17. Генераторы

function*, yield, next(), двусторонний обмен, yield*.

📖 Теория

Генератор — функция, которая может «приостанавливаться» и «возобновляться». Объявляется через function*, приостанавливается через yield.

Каждый вызов генератора возвращает итератор с методом next(). Пока функция не завершится, её состояние сохраняется.

yield — отдаёт значение наружу и приостанавливает. next(value) — возобновляет и передаёт значение внутрь (возвращается из yield).

yield* — делегирование другому итерируемому объекту.

Генераторы используются для:

  • Ленивые последовательности (бесконечные списки)
  • Асинхронные операции (до async/await — co.js, redux-saga)
  • Кастомные итераторы
  • Конечные автоматы

18. Promise

Состояния, then/catch/finally, Promise.all/race/allSettled/any.

📖 Теория

Promise — объект, представляющий результат асинхронной операции. У него три состояния:

  • pending — ожидание
  • fulfilled — выполнено успешно (resolve)
  • rejected — отклонено (reject)

Promise иммутабелен: после перехода из pending в другое состояние изменить нельзя.

Методы:

  • then(onFulfilled, onRejected) — обработка результата
  • catch(onRejected) — синоним then(null, onRejected)
  • finally(fn) — выполнится всегда
  • Promise.all([]) — ждёт все, падает на первой ошибке
  • Promise.allSettled([]) — ждёт все, возвращает статусы
  • Promise.race([]) — первый завершившийся
  • Promise.any([]) — первый успешный (ES2021)

19. async/await

Синтаксический сахар над Promise, обработка ошибок, параллельность.

📖 Теория

async/await (ES2017) — синтаксис, позволяющий писать асинхронный код в синхронном стиле.

async function — всегда возвращает Promise. Внутри неё можно использовать await.

await — приостанавливает выполнение до резолва Promise. Возвращает значение (или бросает ошибку).

Под капотом — генераторы + Promise. Не блокирует поток, но «ждёт» результат асинхронно.

Ошибки: оборачивайте await в try/catch, если ожидаете ошибку.

Параллельность: несколько await подряд — последовательно; Promise.all — параллельно. Разница часто огромна.

Top-level await (ES2022) — можно использовать await на верхнем уровне ES-модуля.

Call stack, task queue, microtasks, макро/микро-задачи, порядок выполнения.

📖 Теория

JS — однопоточный, но асинхронный. Это возможно благодаря event loop — циклу событий, который управляет очередями задач.

Компоненты:

  • Call stack — стек вызовов (где выполняется код)
  • Microtask queue — микрозадачи: промисы, queueMicrotask, MutationObserver
  • Macrotask (task) queue — макрозадачи: setTimeout, setInterval, I/O, UI

Правило: после каждой макрозадачи выполняется ВСЯ microtask queue, потом следующая макрозадача.

Именно поэтому Promise.resolve().then(...) выполняется раньше, чем setTimeout(..., 0).

requestAnimationFrame — особая очередь для анимаций, синхронизируется с обновлением экрана (~60 раз/с).

22. События и делегирование

addEventListener, bubbling, capturing, делегирование, preventDefault.

📖 Теория

Событие — сигнал о том, что что-то произошло (клик, ввод, загрузка). Обработчик регистрируется через addEventListener.

Фазы распространения события:

  • Capturing — сверху вниз (от document к target)
  • Target — сам элемент
  • Bubbling — снизу вверх (от target к document)

Делегирование — вешаем ОДИН обработчик на родителя, а не на каждого потомка. Экономит память и работает с динамически добавленными элементами.

preventDefault — отменить стандартное поведение (переход по ссылке, отправку формы). stopPropagation — остановить всплытие.

Опции: once (один раз), passive (для scroll-оптимизации), capture (capturing-фаза).

23. Fetch и AJAX

fetch API, HTTP-методы, headers, JSON, CORS, обработка ошибок.

📖 Теория

Fetch API — современный способ HTTP-запросов в браузере. Возвращает Promise.

Заменяет старый XMLHttpRequest, работает в Web Workers, поддерживается во всех современных браузерах и в Node.js 18+.

Основные методы: GET (получить), POST (создать), PUT/PATCH (обновить), DELETE (удалить).

Response — объект с методами .json(), .text(), .blob(), .arrayBuffer(). Есть статус, headers, ok, url.

CORS (Cross-Origin Resource Sharing) — механизм контроля доступа между доменами. Сервер должен отдать соответствующие заголовки, иначе браузер заблокирует ответ.

Важно: fetch не падает на HTTP-ошибках (404, 500) — он resolve'ится. Проверяйте response.ok.

24. ES-модули

import/export, default, named, dynamic import, bundlers.

📖 Теория

ES-модули (ESM) — стандартный способ организации кода в современном JS. Заменили CommonJS (require/module.exports) в браузерах и во многом в Node.js.

Экспорт:

  • export const x = 1; — именованный
  • export default function() {} — по умолчанию
  • export { a, b }; — список

Импорт:

  • import { x } from "./mod.js"; — именованный
  • import y from "./mod.js"; — по умолчанию
  • import * as ns from "./mod.js"; — всё
  • import("./mod.js") — динамический (возвращает Promise)

Live bindings: импортированные значения — «живые» ссылки. Если в модуле изменится переменная, изменение отразится у импортирующего.

Bundlers: Vite, Webpack, esbuild, Rollup — собирают модули в бандл для браузера.

25. Ошибки и try/catch

try/catch/finally, throw, Error types, custom errors, асинхронные ошибки.

📖 Теория

try/catch/finally — конструкция обработки ошибок:

  • try — код, который может упасть
  • catch — обработка ошибки
  • finally — выполняется всегда (даже при return)

throw — бросает исключение. Обычно бросают объекты Error.

Встроенные типы ошибок: Error, TypeError, ReferenceError, SyntaxError, RangeError, URIError, EvalError, AggregateError.

Custom errors — наследование от Error для специфичных случаев приложения.

Асинхронность: try/catch ловит только await'нутые ошибки. Promise без await требуют .catch().

27. LocalStorage и Cookies

Web Storage, cookies, sessionStorage, IndexedDB, безопасность.

📖 Теория

Хранение данных на клиенте:

  • localStorage — постоянное (до очистки вручную), ~5-10 МБ
  • sessionStorage — до закрытия вкладки, ~5 МБ
  • Cookies — до 4 КБ, отправляются с каждым HTTP-запросом
  • IndexedDB — большие объёмы (ГБ), асинхронно, структурированные данные
  • Cache API — кеширование ресурсов (для PWA)

localStorage хранит только строки. Для объектов — JSON.stringify/parse.

Cookies имеют атрибуты: HttpOnly (недоступны из JS — защита от XSS), Secure (только HTTPS), SameSite (защита от CSRF), Expires/Max-Age.

Безопасность: никогда не храните токены, пароли и PII в localStorage — любой XSS может их украсть. Для сессий — HttpOnly cookies.

28. WebSocket и realtime

WebSocket API, SSE, long polling, Socket.io, работа с realtime.

📖 Теория

WebSocket — протокол двусторонней связи между клиентом и сервером поверх одного TCP-соединения. В отличие от HTTP, соединение постоянное.

Применения: чаты, realtime-уведомления, котировки, онлайн-игры, совместное редактирование (Google Docs).

Сравнение:

  • HTTP polling — клиент постоянно спрашивает (много запросов)
  • Long polling — сервер держит запрос, пока не появятся данные
  • SSE (Server-Sent Events) — односторонний поток от сервера к клиенту, поверх HTTP
  • WebSocket — полнодуплексный канал

Socket.io — библиотека, оборачивающая WebSocket: автоматический fallback на long polling, комнаты, авто-reconnect.
