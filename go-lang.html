🌟 Почему Go?

Go — компилируемый, статически типизированный язык с автоматическим управлением памятью (GC), богатой стандартной библиотекой и первоклассной поддержкой конкурентности. Создан в Google в 2007 году Робертом Гризмером, Робом Пайком и Кеном Томпсоном.

Go используется в Docker, Kubernetes, Terraform, Prometheus, Grafana, CockroachDB, Uber, Twitch, Dropbox. Идеален для микросервисов, сетевых утилит, DevOps-инструментов и высоконагруженных backend-сервисов.

01. Введение в Go

История, философия языка, ключевые особенности, применение и экосистема.

📖 Что такое Go

Go (Golang) — компилируемый, статически типизированный язык программирования с автоматическим управлением памятью. Разработан в Google в 2007 году, публично анонсирован в 2009, версия 1.0 — в 2012 году.

Создатели — Роберт Гризмер, Роб Пайк и Кен Томпсон (создатель UNIX и B). Все трое — легенды индустрии. Язык задумывался как ответ на проблемы C++ и Java: медленная компиляция, сложная система типов, раздутый синтаксис.

Философия Go:

  • Простота — минималистичный синтаксис, всего 25 ключевых слов
  • Ясность — код важнее «умных» конструкций. Один способ сделать что-то
  • Эффективность — быстрая компиляция, производительность близкая к C
  • Конкурентность — goroutines и channels «из коробки»
  • Стандартная библиотека — HTTP-сервер, JSON, криптография — всё встроено
  • Garbage Collector — автоматическая память, но с низкими паузами
  • Статическая сборка — один бинарник без зависимостей

Ключевые применения: Docker, Kubernetes, Terraform, Prometheus, Etcd, CockroachDB, InfluxDB, Hugo, Caddy. Backend-сервисы в Uber, Twitch, Dropbox, Netflix, American Express.

02. Установка и окружение

Установка Go, GOPATH, модули, go-инструменты, IDE и первые шаги.

📖 Установка

Скачайте SDK с go.dev/dl — установщик для Windows/macOS или архив для Linux. После установки проверьте:

$ go version go version go1.22.0 linux/amd64 $ go env GOROOT="/usr/local/go" GOPATH="/home/user/go" GOMODCACHE="/home/user/go/pkg/mod"

GOROOT — где установлен Go. GOPATH — рабочая директория (по умолчанию ~/go). С версии 1.11 проекты живут в любом месте благодаря модулям, но GOPATH остаётся для кеша.

Модули — современный способ управления зависимостями. Создание проекта:

$ mkdir myapp && cd myapp $ go mod init github.com/user/myapp $ go mod tidy # скачать/удалить неиспользуемые зависимости $ go build # собрать бинарник $ go run main.go # запустить $ go test ./... # все тесты $ go fmt ./... # форматирование (каноничный стиль) $ go vet ./... # статический анализ $ go install ./... # установить бинарник в GOPATH/bin

03. Переменные и типы данных

var, :=, const, iota, базовые типы, приведение, zero values.

📖 Теория

Go — статически типизированный язык. Каждая переменная имеет тип, известный на этапе компиляции. Нельзя изменить тип после объявления (но можно создать новую переменную через конверсию).

Три способа объявить переменную:

  • var x int = 5 — явно с типом (полная форма)
  • var x = 5 — тип выводится из значения
  • x := 5 — короткая форма (только внутри функций)

Zero values (нулевые значения) — переменная без инициализации:

  • Числа: 0
  • Строки: ""
  • Булевы: false
  • Указатели, интерфейсы, срезы, maps, каналы, функции: nil
  • Структуры: значения по умолчанию для всех полей

Базовые типы:

  • Целые: int, int8/16/32/64, uint, uint8/16/32/64, uintptr
  • С плавающей точкой: float32, float64
  • Комплексные: complex64, complex128
  • Строки: string (UTF-8, неизменяемые)
  • Булевы: bool
  • Байты и руны: byte (= uint8), rune (= int32)
  • Ошибки: error (интерфейс)

const — константы времени компиляции. iota — автоинкремент в блоке const (для перечислений).

04. Операторы и выражения

Арифметические, сравнения, логические, битовые, операторы присваивания.

📖 Теория

Go поддерживает стандартный набор операторов, но с минимализмом:

Арифметические: + - * / % (нет **, используйте math.Pow), ++/-- — только постфиксные и как отдельные операторы.

Сравнения: == != < ><= >=. В отличие от JS, == в Go строгий (нет приведения). Сравнение с nil — только с nil-типами.

Логические: && || !. Короткое замыкание работает как ожидается.

Битовые: & | ^ &^ << >>. &^ — AND NOT (используется для очистки битов).

Присваивание: = += -= *= /= %= &= |= ^= <<= >>=. Нет ??=, ||=.

Особенности:

  • Нет тернарного оператора — используйте if/else.
  • Нет перегрузки операторов.
  • Нет неявного приведения: 1 + 2.0 не скомпилируется.
  • ++/-- — операторы, а не выражения (нельзя x = i++).

05. Условия и switch

if/else, switch, type switch, fallthrough, инициализация в условии.

📖 Теория

if/else в Go — без скобок вокруг условия, но фигурные скобки для тела обязательны. Можно объявить переменную прямо в if — она будет видна только в блоке if/else.

switch в Go мощнее, чем в C/Java:

  • Нет проваливания (fallthrough) по умолчанию — break не нужен
  • Можно использовать fallthrough явно, чтобы провалиться
  • Можно писать условия в case: case x > 0:
  • Можно без выражения: switch { case cond: ... }

type switch — switch по типу интерфейса:

switch v := x.(type) { caseint: fmt.Println("int:", v) casestring: fmt.Println("string:", v) casenil: fmt.Println("nil") default: fmt.Printf("unknown: %T", v) }

Go не имеет классического тернарного оператора ? :. Всегда используйте if/else.

06. Циклы (только for)

Единый for, for-range, бесконечный цикл, break/continue, метки.

📖 Теория

В Go только один цикл — for. Нет while, do-while. Все формы выражаются через for.

Формы for:

  • for i := 0; i < n; i++ {} — классический C-стиль
  • for cond {} — как while
  • for {} — бесконечный цикл (выход через break или return)
  • for i, v := range slice {} — по индексам/значениям
  • for k, v := range map {} — по ключам/значениям
  • for i, r := range str {} — по рунам (Unicode)
  • for i := range n {} — Go 1.22+, по диапазону 0..n-1
  • for v := range ch {} — по каналу (до закрытия)

break — выход, continue — следующая итерация. Метки (labels) — для выхода из вложенных циклов.

Важно: до Go 1.22 переменная цикла была одна на все итерации (частая ловушка с замыканиями). В Go 1.22+ — новая переменная на каждой итерации (если loopvar включён).

📖 Теория

Функции в Go — первоклассные объекты. Синтаксис: func name(params) returns { body }.

08. Массивы и срезы

Arrays (фиксированные), slices (динамические), len, cap, append, копирование.

📖 Теория

Массив — [N]T — фиксированная длина N, известная на этапе компиляции. Копируется целиком при присваивании. Используется редко.

Срез (slice) — []T — динамический массив. Это дескриптор из трёх полей: указатель на массив, длина (len) и ёмкость (cap). Сам срез не хранит данные — они в underlying array.

Ключевые операции:

  • s := []int{1, 2, 3} — литерал
  • make([]int, 5) — len=5, cap=5, zero values
  • make([]int, 3, 10) — len=3, cap=10
  • len(s), cap(s) — длина и ёмкость
  • s[i] — доступ, s[i:j] — подсрез (sharing!)
  • append(s, x) — добавление (может переаллоцировать)
  • copy(dst, src) — копирование

append растёт стратегией удвоения (при маленьких размерах) и ~1.25x (при больших). Когда cap исчерпан, создаётся новый underlying array, данные копируются.

Внимание: срезы разделяют underlying array. s2 := s1[1:3] — оба «смотрят» на одни данные, изменение через один видно в другом.

09. Maps (отображения)

Хеш-таблицы, создание, чтение, итерация, безопасность, sync.Map.

📖 Теория

Map — встроенная хеш-таблица «ключ → значение». Тип: map[K]V, где K — сравнимый (comparable) тип: числа, строки, указатели, интерфейсы, структуры из сравнимых полей. Срезы и maps нельзя использовать как ключи.

Создание:

  • m := make(map[string]int)
  • m := map[string]int{"a": 1, "b": 2}
  • var m map[string]int — nil-map (только чтение, запись паникует!)

Операции:

  • m[k] = v — запись
  • v := m[k] — чтение (zero value если нет)
  • v, ok := m[k] — чтение с проверкой (comma-ok idiom)
  • delete(m, k) — удаление
  • len(m) — размер
  • for k, v := range m {} — итерация (случайный порядок)

Порядок обхода не определён — специально. Если нужен стабильный порядок, используйте sorted keys.

Concurrency: обычные maps НЕ потокобезопасны. Для конкурентного доступа — sync.RWMutex или sync.Map.

10. Строки и руны

UTF-8, string, []byte, []rune, strings, strconv, конкатенация.

📖 Теория

string в Go — неизменяемая последовательность байт. Обычно UTF-8, но технически может быть любой. Длина строки в байтах: len(s). Длина в символах (рунах): utf8.RuneCountInString(s) или len([]rune(s)).

Итерация: for i, r := range s даёт позиции в байтах и руны. s[i] — байт, а не символ.

Конкатенация: + — просто, но O(n²) в цикле. Для эффективности — strings.Builder или strings.Join.

Пакет strings: Contains, HasPrefix, HasSuffix, Split, Join, Trim, Replace, ToUpper, ToLower, Index, Count, Repeat, Fields.

strconv: Itoa, Atoi, ParseInt, ParseFloat, FormatInt.

11. Указатели

*T, &, nil, new, make, escape analysis, зачем нужны указатели.

📖 Теория

Указатель — переменная, хранящая адрес другой переменной. Тип: *T (указатель на T). Нулевое значение — nil.

Операторы:

  • &x — взять адрес переменной
  • *p — разыменовать (получить значение по адресу)
  • new(T) — создать указатель на zero value T

Зачем указатели:

  • Передача по ссылке: чтобы функция могла изменить значение
  • Избежать копирования больших структур
  • Разделять состояние между частями программы
  • Nullable-семантика: *T может быть nil
  • В методах — pointer receiver для мутации получателя

Go-особенности:

  • Нет арифметики указателей (в отличие от C/C++)
  • Автоматическое разыменование: p.field вместо (*p).field
  • Escape analysis: компилятор решает, где жить — стек или куча
  • Нет висячих указателей: GC не даст освободить используемую память

12. Структуры (struct)

Объявление, инициализация, вложение, embedding, теги, memory layout.

📖 Теория

struct — составной тип, объединяющий поля разных типов. Это «конструктор» для создания собственных типов. Struct — value type: копируется при присваивании и передаче.

Объявление:

type User struct { Name string Age int Email string }

Инициализация:

  • User{"Alice", 30, "a@x.com"} — позиционно (хрупко, не рекомендуется)
  • User{Name: "Alice", Age: 30} — с именами полей (рекомендуется)
  • &User{...} — указатель
  • new(User) — указатель на zero struct

Embedding — вложение без имени поля: type Admin struct { User; Role string }. Даёт «повышение» методов и полей — композиция вместо наследования.

Теги — метаданные для сериализации, валидации, ORM: json:"name,omitempty". Читаются через reflection.

Порядок полей влияет на размер: из-за выравнивания компилятор может добавить padding.

13. Методы

Value vs pointer receiver, method sets, автоприведения, методы на любых типах.

📖 Теория

Метод — функция, привязанная к типу через «receiver». Объявление:

func (u User) Name() string { ... } // value receiverfunc (u *User) SetName(n string) { ... } // pointer receiver

Value receiver — получает копию. Не может мутировать оригинал. Используется для read-only операций.

Pointer receiver — получает указатель. Может мутировать. Работает для больших struct (избежать копирования).

Правила выбора:

  • Если нужно изменить получателя — только pointer
  • Если struct большая (> 3-4 слов) — pointer для производительности
  • В остальных случаях — value (безопаснее, работает с nil)
  • Единообразие важно: если хоть один метод — pointer, делайте все pointer

14. Интерфейсы

📖 Теория

15. Обработка ошибок

error, возврат ошибок, обёртывание, errors.Is/As, sentinel errors, custom errors.

📖 Теория

В Go нет исключений (try/catch). Ошибки — это обычные значения типа error (интерфейс с одним методом Error() string).

Стандартный паттерн: функция возвращает (T, error). Проверка if err != nil { return ..., err } — везде.

Способы создания ошибок:

  • errors.New("message") — простая ошибка
  • fmt.Errorf("context: %w", err) — обёртка с сохранением оригинальной ошибки
  • Свои типы, реализующие error — для структурированных ошибок

Обёртывание (с Go 1.13): %w создаёт цепочку ошибок. Разворачивается через errors.Unwrap, проверяется через errors.Is / errors.As.

Sentinel errors — экспортируемые переменные-ошибки: io.EOF, sql.ErrNoRows. Проверяются через errors.Is.

Custom error types — структуры, реализующие error. Позволяют хранить дополнительные данные. Проверяются через errors.As.

Принципы:

  • Не игнорируйте ошибки (кроме случаев, когда явно понимаете последствия)
  • Добавляйте контекст через %w, а не теряйте информацию
  • Ошибки — часть API. Думайте о них как о типах
  • Не паникуйте в библиотеках — возвращайте ошибку

16. Panic, recover, defer

Аварийные ситуации, восстановление, когда НЕ использовать panic, порядок defer.

📖 Теория

panic — аварийное завершение программы. Вызывается явно (panic("msg")) или автоматически (nil pointer, out of bounds, деление на 0). После паники выполняются все отложенные defer'ы, затем программа падает.

recover — восстановление после паники. Работает только внутри defer. Возвращает значение паники.

defer — отложенный вызов. Выполняется при выходе из функции (в том числе при панике), LIFO-порядок.

Правила использования:

  • panic — только для «непоправимых» ситуаций: битый инвариант, ошибка программиста, невозможное состояние
  • Возврат ошибки — для «ожидаемых» ошибок: файл не найден, неверный пароль, network timeout
  • recover — для изоляции: HTTP-сервер ловит паники в хэндлерах, чтобы не уронить всё
  • НЕ используйте recover как try/catch для обычных ошибок

Порядок defer: LIFO (последний добавленный выполняется первым). Аргументы defer вычисляются сразу при регистрации.

18. Горутины

go, GMP-модель, синхронизация, sync.WaitGroup, утечки горутин.

📖 Теория

Горутина — легковесный поток, управляемый runtime Go. Создаётся через go func(). Стоимость запуска — ~2 КБ стека (против 8 МБ у OS-потока).

GMP-модель (Go scheduler):

  • G — goroutine
  • M — machine (OS thread)
  • P — processor (контекст выполнения, по умолчанию = NumCPU)

Runtime планирует G на P на M. Когда G блокируется (I/O, channel), P берёт другую G. Это M:N scheduling — миллионы горутин на нескольких потоках.

Свойства:

  • Не блокируют друг друга при правильном использовании
  • Запускаются с GOMAXPROCS P-контекстами параллельно
  • Легко создавать: тысячи, десятки тысяч — норма

Опасности:

  • Гонки данных (data races) — одновременный доступ без синхронизации
  • Утечки горутин — горутина никогда не завершится (висящий канал, бесконечный цикл)
  • Не паникует — паника в одной горутине роняет всю программу
  • main завершится — программа завершается, когда main вернулся, а не когда все горутины закончились

19. Каналы

chan, буферизованные, направленные, select, закрытие, range по каналу.

📖 Теория

Канал — типизированный «pipe» для коммуникации между горутинами. Создаётся через make(chan T). Это ссылочный тип.

Синтаксис:

  • ch <- value — отправить (блокируется, если некому принимать)
  • value := <-ch — получить (блокируется, пока не пришлют)
  • close(ch) — закрыть канал
  • v, ok := <-ch — получить с проверкой закрытия
  • for v := range ch {} — читать до закрытия

Буферизованные: make(chan int, 5) — можно отправить 5 без блокировки. При заполнении — блок.

Направленные: chan<- T (только отправка), <-chan T (только получение). Ограничивают API.

Правила:

  • Закрывает только отправитель (никогда получатель)
  • Не закрывайте канал, если есть вероятность отправки
  • Отправка в закрытый канал — паника
  • Чтение из закрытого канала — zero value + ok=false
  • Закрывать нужно не всегда — GC соберёт мусор

20. Select и sync

📖 Теория

select — мультиплексирование каналов, как switch для каналов. Работает с несколькими case, выполняет один из готовых. Если ни один не готов — ждёт (или default).

  • sync.Pool — пул временных объектов (снизить GC)
  • sync.Map — потокобезопасная map (для особых случаев)

atomic — операции над int32/int64/pointer без блокировок: Add, Load, Store, CompareAndSwap.

21. Context

Отмена, таймауты, дедлайны, передача значений, правила использования.

📖 Теория

context.Context — стандартный способ передачи сигналов отмены, таймаутов и request-scoped значений через границы API. Появился в Go 1.7.

Создание:

  • context.Background() — базовый, никогда не отменяется (для main, init)
  • context.TODO() — заглушка, когда контекст ещё не продуман
  • context.WithCancel(parent) — отмена вручную
  • context.WithTimeout(parent, d) — автоотмена через duration
  • context.WithDeadline(parent, t) — автоотмена в конкретное время
  • context.WithValue(parent, key, val) — передача значений

Методы:

  • ctx.Done() — канал, закрывается при отмене
  • ctx.Err() — причина отмены (Canceled / DeadlineExceeded)
  • ctx.Deadline() — время дедлайна
  • ctx.Value(key) — получить значение

Правила:

  • Context — первый параметр функции: func foo(ctx context.Context, ...)
  • Не храните Context в struct — передавайте явно
  • Не передавайте nil — используйте context.TODO()
  • Не используйте для опциональных параметров — только для request-scoped (request ID, trace, auth)
  • Только для отмены, таймаутов, метаданных — не для бизнес-логики

22. Generics (обобщения)

Type parameters, constraints, ~T, comparable, обобщённые структуры, ограничения.

📖 Теория

Generics появились в Go 1.18 (март 2022). Позволяют писать код, параметризованный типами. До этого — только интерфейсы и reflect (медленно и небезопасно).

Синтаксис:

funcMax[T comparable](a, b T) T { if a > b { return a } return b }

Type parameter T — заполнитель для типа. Constraint — ограничение (интерфейс), каким типам можно подставлять.

Встроенные constraints:

  • any — любой тип (= interface{})
  • comparable — поддерживает == и !=
  • ~T — все типы с underlying типом T (например, ~int — int, MyInt, YourInt)
  • Объединение: int | int64 | float64

Обобщённые структуры:

type Stack[T any] struct { items []T }

Ключевое правило Go: используйте генерики осторожно. Часто интерфейс проще и читаемее. Generics — для контейнеров и алгоритмов, где действительно нужно.

23. Reflection

reflect.Type, reflect.Value, Kind, теги, динамический вызов, опасности.

📖 Теория

Reflection — возможность анализировать и изменять типы во время выполнения. Обычно не нужен в повседневном коде, но критичен для библиотек: encoding/json, ORM, валидаторы, DI-контейнеры.

Два типа:

  • reflect.Type — метаинформация о типе (имя, kind, поля, методы)
  • reflect.Value — значение с возможностью чтения/записи

Основные операции:

  • reflect.TypeOf(x) — получить Type
  • reflect.ValueOf(x) — получить Value
  • v.Kind() — базовый вид (Struct, Int, String, Slice...)
  • v.Interface() — вернуть как interface{}
  • t.NumField(), t.Field(i) — поля struct
  • v.Field(i) — значение поля
  • v.Set(...) — установить (нужен указатель)

Правила:

  • Reflection медленный — не используйте в горячих путях
  • Reflection небезопасен — проверяйте Kind, IsValid, CanSet
  • Часто есть альтернатива: code generation, интерфейсы
  • Reflection «обходит» систему типов — используйте с умом

24. Тестирование

📖 Теория

Go имеет тестирование «из коробки»: пакет testing, файлы *_test.go, команда go test. Не нужно устанавливать фреймворки (хотя testify, ginkgo популярны).

26. JSON и сериализация

encoding/json, теги, кастомный маршалинг, protobuf, другие форматы.

📖 Теория

encoding/json — стандартный пакет для JSON. json.Marshal (в байты), json.Unmarshal (из байт). Для потоков — json.Encoder/json.Decoder.

Теги struct управляют сериализацией:

  • json:"name" — имя поля
  • json:"name,omitempty" — пропустить если zero value
  • json:"-" — игнорировать поле
  • json:",string" — сериализовать как строку

Правила:

  • Поля должны быть экспортированы (с большой буквы)
  • map с ключами string → JSON object
  • map с другими ключами — ошибка (в Go 1.16+ поддерживается encoding.TextMarshaler)
  • nil → null для указателей, интерфейсов
  • Разница: []T(nil) → null, []T{} → []

Кастомный маршалинг — реализация MarshalJSON / UnmarshalJSON.

Другие форматы: XML (encoding/xml), YAML (gopkg.in/yaml.v3), TOML, MessagePack, Protobuf (protoc, faster + smaller).

27. Сеть и HTTP

net/http, сервер, клиент, middleware, gin/echo, REST API.

📖 Теория

Go — один из лучших языков для сетевых приложений благодаря встроенной стандартной библиотеке net/http.

28. Базы данных и SQL

📖 Теория

Стандартный пакет database/sql — универсальный интерфейс к SQL-базам. Работает через драйверы: pq/pgx (PostgreSQL), go-sql-driver/mysql, mattn/go-sqlite3.

29. Производительность

pprof, benchmarking, escape analysis, аллокации, GC, профилирование в проде.

📖 Теория

Go — быстрый язык, но не «магический». Производительность требует измерений и профилирования.

Инструменты:

  • go test -bench — бенчмарки
  • go test -benchmem — аллокации
  • pprof — CPU/memory/goroutine/block/mutex профили
  • go test -cpuprofile, -memprofile, -trace
  • runtime/trace — детальный трейс планировщика
  • escape analysis (go build -gcflags="-m")
  • go tool benchstat — сравнение бенчмарков

Ключевые оптимизации:

  • Меньше аллокаций (избегать ненужных new, use stack where possible)
  • sync.Pool для частых временных объектов
  • strings.Builder вместо конкатенации
  • Предаллокация срезов: make([]T, 0, n)
  • Избегать interface{} в горячем пути
  • Pointer receiver для больших struct
  • Буферизованные каналы для producer-consumer

GC в Go — concurrent, с малыми паузами (< 1 мс). Настраивается через GOGC (по умолчанию 100 = в 2 раза больше heap).
