Kotlin разработан как «лучшая Java» — прагматичный, безопасный, лаконичный. Работает на 60%+ профессиональных Android-разработчиков. Входит в топ-15 языков по популярности по TIOBE, Stack Overflow, GitHub.

01. Введение в Kotlin

История, философия, применение, платформы, JVM, экосистема.

📖 Что такое Kotlin

Kotlin — статически типизированный, мультипарадигменный язык, официальный язык Android. Создан компанией JetBrains (разработчики IntelliJ IDEA, ReSharper) в 2011 году, стабильная версия 1.0 вышла в феврале 2016. Название — по острову Котлин под Санкт-Петербургом.

Ключевые особенности:

  • Null safety — система типов отделяет nullable и non-null
  • 100% совместимость с Java — можно использовать любые Java-библиотеки
  • Корутины — лёгкие потоки для асинхронности
  • Extension-функции — расширение чужих классов
  • Data classes — автогенерация equals/hashCode/toString/copy
  • Sealed classes — безопасный pattern matching
  • Type inference — минимум аннотаций типов
  • Мультиплатформенность — JVM, Android, JS, Native, WASM
  • Функциональный стиль — лямбды, higher-order functions, immutable коллекции
  • Лаконичность — в 2–3 раза меньше кода, чем в Java

Платформы:

  • JVM — backend, Android, серверные приложения, Gradle
  • Android — Google объявил Kotlin официальным в 2017 году
  • JavaScript — frontend, Node.js
  • Native — iOS, macOS, Linux, Windows, embedded
  • WASM — WebAssembly (Kotlin/Wasm)
  • KMP (Kotlin Multiplatform) — shared code между платформами

Компании, использующие Kotlin: Google, JetBrains, Pinterest, Square, Trello, Evernote, Uber, Netflix, Cash App, Revolut, Twitter (backend), Atlassian, Shopify.

03. Переменные и типы данных

val, var, примитивы, String, type inference, приведение типов.

📖 Теория

Kotlin — статически типизированный язык с type inference (выводом типов).

val — immutable (только для чтения, аналог final). var — mutable (изменяемая).

val x = 42var y = 10 y = 20val name: String = "Alice"val age: Int = 30

Примитивы:

  • Byte — 8 бит, −128..127
  • Short — 16 бит, −32768..32767
  • Int — 32 бита, −2³¹..2³¹−1
  • Long — 64 бита, суффикс L: 42L
  • Float — 32 бита, суффикс f: 3.14f
  • Double — 64 бита, по умолчанию для дробных
  • Boolean — true/false
  • Char — Unicode символ (2 байта)
  • String — строка (immutable)

Приведение типов: Kotlin не делает автоматическое расширение для чисел (Int → Long)!

val i: Int = 42val l: Long = i.toLong() val d: Double = i.toDouble() val s: String = i.toString()

Улучшения над Java:

  • Нет явных примитивов — всё объекты (но JVM оптимизирует)
  • String templates: "Hello, $name"
  • Unsigned типы: UInt, ULong, UByte, UShort
  • Type inference: редко нужно писать типы явно

04. Операторы и выражения

Арифметика, сравнение, логика, элвис, range, инкремент.

📖 Теория

Kotlin имеет все привычные операторы + свои особенности.

Арифметические: + - * / %. Деление целых — целочисленное.

Инкремент/декремент: ++ --. Префиксные и постфиксные.

Сравнение: == != < > <= >=. ВАЖНО: == в Kotlin вызывает equals(), а не сравнивает ссылки! Для ссылок — ===.

val a = "hello"val b = "hello" a == b a === b

Логические: && || !. Короткое замыкание.

Битовые: в Kotlin нет & | ^ << >> для чисел — используются методы: and(), or(), xor(), shl(), shr(), inv().

Элвис?:: a ?: b — если a null, вернуть b.

Безопасный вызов?.: a?.length — если a null, вернуть null.

!! — «not null» assertion (бросает NPE).

Тернарный: нет! Используйте if-else как выражение.

val max = if (a > b) a else b

Range: .., until, downTo, step.

in: проверка принадлежности: x in 1..10.

is: проверка типа: x is String.

as: приведение: x as String. as? — безопасное.

05. Условия и when

if/else как выражение, when (statement и expression), smart casts.

📖 Теория

if/else в Kotlin — выражение, возвращает значение. Нет тернарного оператора (не нужен).

val max = if (a > b) a else b val status = if (score >= 90) "A"else if (score >= 80) "B"else"C"

when — мощная замена switch. Может быть statement или expression:

when (x) { 1 -> println("one") 2, 3 -> println("two or three") in4..6 -> println("four to six") isString -> println("string!") else -> println("other") }

when как выражение:

val result = when (status) { 200, 201 -> "success"404 -> "not found"else -> "unknown" }

Особенности when:

  • Не требует break (нет fall-through)
  • Может проверять диапазоны: in 1..10
  • Может проверять типы: is String
  • Может не иметь аргумента: when { cond1 -> ...; cond2 -> ... }
  • Требует else или быть exhaustive (для sealed/enum)

Smart cast: компилятор автоматически приводит тип после проверки:

val obj: Any = "hello"if (obj isString) { println(obj.length) }

06. Циклы и диапазоны

for, while, do-while, ranges, break/continue, labels, repeat.

📖 Теория

for в Kotlin — это foreach (по диапазону или коллекции). Классического C-style for (int i = 0; i < 10; i++) нет!

for (i in1..5) { } for (i in0 until 10) { } for (i in10 downTo 1) { } for (i in1..10 step 2) { } for (item in list) { } for ((index, value) in list.withIndex()) { }

while и do-while — как везде:

while (condition) { } do { } while (condition)

repeat(n) — цикл без счётчика:

repeat(5) { println("Hello") }

break — выход, continue — следующая итерация. Labels — для вложенных циклов:

outer@ for (i in1..3) { for (j in1..3) { if (i * j == 4) break@outer } }

return из forEach — non-local return (только для inline-функций):

list.forEach { if (it > 5) return }

Основной цикл: for (i in list.indices) вместо C-style.

Array, List, Set, Map, Sequence — различия и выбор.

📖 Теория

В Kotlin нет примитивных массивов (как int[] в Java). Вместо них:

  • Array<T> — обычный массив объектов
  • IntArray, LongArray, DoubleArray, ... — примитивные (для производительности)

val seq = list.asSequence() .filter { it > 0 } .map { it * 2 } .toList()

  • List — упорядоченная, индексы, дубликаты
  • Set — уникальные, без порядка (LinkedHashSet — с порядком)
  • Map — ключ-значение
  • Sequence — ленивая обработка
  • Array — для JVM-интеропа и производительности

09. Функции

📖 Теория

Возвращаемый тип: Unit (аналог void) — можно не указывать. Nothing — никогда не возвращается (throw).

11. Data-классы

data class, copy, destructuring, componentN, equals/hashCode.

📖 Теория

data class — класс для хранения данных. Компилятор автоматически генерирует:

  • equals() и hashCode() — по всем полям

  • equals/hashCode генерируются по primary constructor
  • Если переопределить equals вручную — не генерируется
  • Не data-класс, но похожие: value class (inline class), enum class, object

12. Наследование и интерфейсы

open, override, abstract, interface, delegation, super.

📖 Теория

В Kotlin все классы final по умолчанию. Для наследования — open. Методы тоже final по умолчанию.

open classAnimal(val name: String) { open funspeak() = "..." } classDog(name: String) : Animal(name) { override funspeak() = "Woof" }

Интерфейсы — как в Java 8+: с default-реализациями.

interfaceShape { funarea(): Doublefundescribe() = "Area: ${area()}" }

Множественное наследование интерфейсов — можно. Конфликт default-методов решается явно через super<Interface>.method().

Ключевые правила:

  • open — разрешает наследование/переопределение
  • override — обязательное переопределение
  • final override — запрет дальнейшего переопределения
  • super.method() — вызов родительской реализации
  • abstract — без реализации, требует переопределения
  • sealed — ограниченный набор наследников (раздел 14)

Делегирование — вместо наследования: class B(a: A) : A by a — все методы A делегируются в a. Идеально для композиции.

💡 Kotlin поощряет композицию вместо наследования. Наследование — только для настоящих «is-a».

14. Sealed классы и enum

sealed class, sealed interface, exhaustive when, enum с полями.

📖 Теория

sealed class — класс с ограниченным набором наследников. Все наследники должны быть в том же пакете/модуле.

sealed classResult { data classSuccess(val data: String) : Result() data classError(val code: Int) : Result() objectLoading : Result() }

Зачем:

  • Exhaustive when — компилятор проверяет, что все случаи обработаны
  • Type-safe state machines — UI state, результаты
  • Ограничение наследования — никто снаружи не добавит новый подтип
  • Работает с when как expression

Sealed interface (Kotlin 1.5+) — то же для интерфейсов. Позволяет множественное наследование.

enum class — фиксированный набор констант. Может содержать поля, методы, конструкторы.

enum classStatus(val code: Int) { OK(200), NOT_FOUND(404), ERROR(500); funisSuccess() = code < 400 }

sealed vs enum:

  • enum — константы (синглтоны), могут иметь поля, но нет иерархии подтипов
  • sealed — подтипы могут быть data class с разными полями
💡 Правило: enum — для фиксированного набора значений, sealed — для типов с разной структурой.

  • Нет примитивов в дженериках (используются боксы)

18. Null safety

?, ?., ?:, !!, let, lateinit, безопасная работа с null.

📖 Теория

Null safety — ключевая особенность Kotlin. Система типов отличает nullable и non-nullable:

var a: String = "hello"var b: String? = null

Операторы:

  • ?. — безопасный вызов: b?.length → Int?
  • ?: — элвис: b ?: "default"
  • !! — «not null» (бросает NPE если null)
  • ?. цепочки: a?.b?.c?.d
  • let — безопасная работа: b?.let { ... }

Smart cast: компилятор автоматически считает non-null после проверки:

if (b != null) { println(b.length) }

lateinit — отложенная инициализация (только var, non-primitive):

lateinit var name: String name = "Alice"

by lazy — ленивая инициализация (val, только геттер):

val config bylazy { loadConfig() }

Платформенные типы: String! — из Java, могут быть null. Kotlin не проверяет. Ответственность на вас.

⚠️ !! — зло. Используйте ?:, ?.let, requireNotNull вместо !!. Если вы пишете !! — спросите себя, почему бы не обработать null?
💡 Null safety в Kotlin — не магия. Данные из БД, JSON, Java-интеропа могут быть null. Используйте ? и ?: — код будет безопасным и читаемым.

📖 Теория

Extension-функции — возможность добавить метод к существующему классу без наследования:

Extension properties:

funUser.Companion.createGuest() = User("Guest") User.createGuest()

21. Корутины — основы

📖 Теория

Корутины — лёгкие потоки для асинхронного программирования. Основа — библиотека kotlinx.coroutines.

import kotlinx.coroutines.* funmain() = runBlocking { launch { delay(1000) println("World") } println("Hello") }

Ключевые понятия:

  • suspend — функция может приостанавливаться (не блокирует поток)
  • launch — запустить корутину (возвращает Job)
  • async — запустить с результатом (возвращает Deferred)
  • runBlocking — блокирующий bridge в main
  • CoroutineScope — контекст жизненного цикла
  • Dispatchers — где запускать (Main, IO, Default)
  • Job — handle для отмены/join
  • await — получить результат Deferred

Преимущества:

  • Миллионы корутин на одном потоке
  • Структурированная конкурентность (structured concurrency)
  • Отмена через CoroutineScope
  • Читаемый код (как синхронный)
  • Не блокируют поток во время delay

Dispatchers:

  • Main — UI поток (Android)
  • IO — блокирующие операции (сеть, файлы)
  • Default — CPU-intensive
  • Unconfined — без ограничений (осторожно)
⚠️ Не блокируйте потоки внутри корутин — используйте delay, withContext, не Thread.sleep.

22. Корутины — продвинутое

Flow, StateFlow, SharedFlow, Channel, операторы, backpressure.

📖 Теория

Flow — асинхронный поток данных (аналог Sequence + suspend). Холодный по умолчанию.

funnumbers(): Flow<Int> = flow { for (i in1..10) { delay(100) emit(i) } }

StateFlow — hot-flow с текущим значением (аналог LiveData, только для Compose/ViewModel).

SharedFlow — hot-flow для событий (broadcast).

Channel — очередь между корутинами (для producer-consumer).

Flow операторы (главное преимущество):

  • Трансформация: map, filter, transform, take, drop
  • Агрегация: reduce, fold, count
  • Комбинация: zip, combine, merge, flatMapConcat, flatMapMerge, flatMapLatest
  • Context: flowOn, buffer, conflate, collectLatest
  • Side effects: onStart, onCompletion, onEach, catch, retry

Backpressure: buffer, conflate, collectLatest — стратегии работы при медленном коллекторе.

Когда Flow vs Sequence:

  • Sequence — синхронные вычисления (CPU-bound)
  • Flow — асинхронные (I/O, delays, suspend)
💡 Best practice: во ViewModel — StateFlow (single source of truth), события — SharedFlow или Channel. В Compose — collectAsStateWithLifecycle.

23. Исключения

try/catch/finally, checked vs unchecked, Result, runCatching.

📖 Теория

В Kotlin нет checked exceptions — все исключения unchecked. Это упрощает API, но требует внимательности.

try { throwRuntimeException("error") } catch (e: Exception) { println(e.message) } finally { }

Иерархия:

  • Throwable — корень
  • Error — серьёзные (OutOfMemoryError)
  • Exception — обычные
    • RuntimeException — NPE, IllegalArgument, IllegalState
    • IOException, SQLException

Идиоматичный Kotlin — Result:

funparse(s: String): Result<Int> = runCatching { s.toInt() }

Result — sealed класс: Success(value) или Failure(exception). Преимущества:

  • Явный контракт (видно, что может упасть)
  • Функциональная обработка: map, fold, getOrNull
  • Не теряет stack trace

try/catch как выражение:

val result = try { riskyOp() } catch (e: Exception) { null }

Правила:

  • Ловите конкретные исключения
  • Не глотайте (пустой catch)
  • Не используйте исключения для flow control
  • В корутинах — обязательно пробрасывать CancellationException
  • Result — для public API, где важно показать возможность ошибки
⚠️ CancellationException в корутинах — не ловите её как обычное исключение. Всегда пробрасывайте дальше, иначе корутина не отменится!

Lead-разработчик Kotlin — не только самый продуктивный программист, но и технический лидер команды. Ключевые задачи:

  • Архитектура: выбор стека, паттерны, trade-offs, ADR
  • Code review: качество кода, обучение через код
  • Менторство: рост junior/middle, карьерные планы
  • Планирование: оценка, декомпозиция, roadmap
  • Коммуникация: с продуктом, дизайном, стейкхолдерами
  • DevOps: CI/CD, мониторинг, инциденты, on-call
  • Найм: собеседования, onboarding

  • Глубокое знание JVM, корутин, GC

📐 Принципы хорошего Lead

  • «Не пиши код, пиши людей» — главная задача Lead — вырастить команду.
  • Technical Debt — осознанно принимайте решения. Обсуждайте с бизнесом.
  • Observability: logs + metrics + traces = 3 столпа.
  • Инциденты: blameless postmortem, root cause analysis, action items.
  • Code review: учите, не стыдите. Особенно с корутинами — race conditions невидимы.
  • ADR (Architecture Decision Records) — фиксируйте решения.
  • DORA-метрики: deployment frequency, lead time, MTTR, change failure rate.
  • Менторство: 1-on-1, обратная связь, карьерные планы.
  • Документация: README, KDoc, OpenAPI, runbooks.
  • Автоматизация: Detekt, ktlint, тесты — всё в CI.
  • Version catalogs (Gradle) — централизованные зависимости.
  • Compose first — новый UI на Compose, не XML.
  • Coroutines с умом — не блокируйте, отменяйте, тестируйте.
  • Compile-time safety — sealed, value class, @JvmInline.
  • Готовность к KMP — держите бизнес-логику platform-agnostic.
  • Технологический радар: Kotlin 2.0, K2, Compose MP, WASM.
