🌟 Почему Rust?

Rust — компилируемый, статически типизированный язык без сборщика мусора с гарантиями безопасности памяти и потоков на этапе компиляции. 7 лет подряд признаётся самым любимым языком по опросам Stack Overflow.

Создан Mozilla в 2010-2015, стабилен с 2015. Используется в Firefox, Windows, Linux, Dropbox, Cloudflare, AWS, Discord, Figma, Microsoft. Идеален для системного программирования, WebAssembly, CLI, embedded, блокчейна и высоконагруженных сервисов.

Девиз: «Blazing fast, memory safe, productive». Скорость C/C++, безопасность Java/Python, инструменты будущего.

01. Введение в Rust

История, философия, применение, экосистема, место в индустрии.

📖 Что такое Rust

Rust — компилируемый, статически типизированный язык системного программирования. Создан в Mozilla Research: разработка начата в 2006 году Грейдоном Хоаром как личный проект, в 2009 присоединился Mozilla, стабильная версия 1.0 — в мае 2015.

Ключевые свойства:

  • Безопасность памяти без GC — ownership и borrowing
  • Безопасность потоков — Send/Sync-типы, data race-free
  • Zero-cost abstractions — высокоуровневый код, низкоуровневая скорость
  • Никаких null — Option вместо них
  • Никаких исключений — Result явно
  • Fearless concurrency — параллелизм без страха
  • Отличный toolchain — cargo, rustfmt, clippy, rustdoc
  • Строгий borrow checker — ошибки на этапе компиляции, а не в продакшене

Применение: системные утилиты (ripgrep, fd, bat), web-серверы (Actix, Axum), WebAssembly, blockchain (Solana, Polkadot), embedded, ОС (Redox), game engines, криптография, CLI-инструменты.

03. Переменные и mutability

let, mut, shadowing, const, static, immutability по умолчанию.

📖 Теория

Ключевая особенность Rust: переменные неизменяемы по умолчанию. Чтобы разрешить изменение, нужен mut.

let x = 5; let mut y = 5; y = 10; const MAX: u32 = 100; static GLOBAL: u32 = 42;

Shadowing — можно заново объявить переменную с тем же именем. Это не изменение, а создание новой.

let x = 5; let x = x + 1; // новая переменная, старую «затенили» let x = "hello"; // можно даже сменить тип!

Отличия const от let:

  • const — константа времени компиляции, требует явного типа
  • const — не может быть mut
  • const можно объявлять в любой области видимости
  • const не имеет фиксированного адреса (может инлайниться)
  • static — имеет фиксированный адрес, живёт всю программу
  • static mut — требует unsafe для доступа

04. Типы данных

Скалярные, составные, String vs &str, приведение типов.

📖 Теория

Rust — строго типизированный язык. Типы делятся на скалярные и составные.

Скалярные типы:

  • Целые: i8, i16, i32, i64, i128, isize, u8...u128, usize
  • С плавающей точкой: f32, f64
  • Булевы: bool (true/false)
  • Символы: char (Unicode, 4 байта)

Составные типы:

  • Кортежи: (T1, T2, ...) — фиксированный размер
  • Массивы: [T; N] — фиксированная длина

String vs &str:

  • String — owned, heap, изменяемая
  • &str — borrowed, чаще в стеке или в бинарнике

Приведение типов — через as (только для чисел и указателей): 3.14 as i32 = 3.

05. Функции

fn, параметры, возврат, выражения, ранние return, diverging functions.

📖 Теория

Функции объявляются через fn. Параметры типизированы явно. Возврат — через -> Type.

fn add(a: i32, b: i32) -> i32 { a + b }

Важно: в Rust почти всё — выражение. Последнее выражение в блоке {} — возвращаемое значение (без ;). Если добавить ; — получится statement, функция вернёт ().

Характеристики:

  • snake_case для имён функций
  • Явные типы в сигнатуре
  • Порядок не важен — можно вызывать до объявления
  • Функции как значения — можно передавать как аргументы
  • Diverging functions — тип ! (никогда не возвращает): panic!, exit, loop без break

06. Управление потоком

📖 Теория

if/else — выражение в Rust, может возвращать значение. Условие должно быть bool (никакой «истинности» как в Python/JS).

Циклы:

  • loop — бесконечный, с break можно вернуть значение

// loop возвращает значение let result = loop { break 42; // результат loop };

07. Владение (ownership)

Главная идея Rust: move, copy, drop, ownership rules, без GC.

📖 Теория

Ownership — фундамент Rust. Каждое значение имеет ровно одного владельца. Когда владелец выходит из области видимости — значение автоматически освобождается.

Три правила ownership:

  1. Каждое значение имеет ровно одного владельца
  2. В каждый момент времени может быть только один владелец
  3. Когда владелец выходит из области видимости — значение уничтожается (drop)

Move: при присваивании или передаче в функцию владение перемещается. Старая переменная становится невалидной.

let s1 = String::from("hello"); let s2 = s1; // ownership перешёл к s2 // println!("{}", s1); // ошибка: value borrowed after move

Copy: простые типы (числа, bool, char, кортежи из Copy) копируются вместо перемещения. Для них move = copy.

Clone: явное глубокое копирование через .clone() — дорого, но иногда нужно.

Drop: автоматический вызов при выходе из области видимости. Аналог деструктора, но автоматический.

08. Заимствование (borrowing)

Ссылки &T и &mut T, правила borrow checker, NLL, борьба с типичными ошибками.

📖 Теория

Borrowing — способ получить доступ к данным, не забирая владение. Через ссылки: &T (immutable) и &mut T (mutable).

Правила заимствования:

  • Можно иметь много immutable ссылок (&T) одновременно
  • Можно иметь ровно одну mutable ссылку (&mut T)
  • Нельзя одновременно immutable и mutable
  • Ссылки всегда валидны (нет висячих указателей)

Эти правила проверяются borrow checker'ом на этапе компиляции. Это гарантирует отсутствие data race и висячих указателей.

Non-Lexical Lifetimes (NLL) — с Rust 2018 borrow проверяется по фактическому использованию, а не по лексическому scope. Это делает код более гибким.

Типичные ошибки:

  • Изменить данные, пока есть immutable ссылка
  • Вернуть ссылку на локальную переменную
  • Иметь два mutable заимствования одновременно

🎮 Интерактив: правила заимствования

—

📐 Примеры

// Immutable ссылки let s = String::from("hello"); let r1 = &s; let r2 = &s; // OK — много immutable println!("{} {}", r1, r2); // Mutable ссылка let mut s2 = String::from("hello"); let rm = &mut s2; rm.push_str(" world"); println!("{}", rm); // Нельзя одновременно & и &mut let mut s3 = String::from("hello"); let r = &s3; // let rm2 = &mut s3; // ❌ ошибка println!("{}", r); let rm2 = &mut s3; // OK — r больше не используется // Функции, принимающие ссылки fn calculate_length(s: &String) -> usize { s.len() } let str1 = String::from("hello"); let len = calculate_length(&str1); // передаём ссылку println!("{} has {} chars", str1, len); // str1 валидна! // Mutable функция fn append(s: &mut String) { s.push_str(" world"); } let mut str2 = String::from("hello"); append(&mut str2); println!("{}", str2); // "hello world" // Проблема: изменить пока borrowed let mut nums = vec![1, 2, 3]; let first = &nums[0]; // nums.push(4); // ❌ пока first в scope println!("{}", first); nums.push(4); // OK — first больше не используется // NLL — borrow заканчивается на последнем использовании fn get_first(words: &[String]) -> &String { &words[0] } // Возврат ссылки из функции требует lifetime fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { if x.len() > y.len() { x } else { y } } // Reborrow fn process(s: &mut String) { let s2 = &mut *s; // reborrow s2.push_str("!"); } // Deref: &String работает как &str fn takes_str(s: &str) { } let owned = String::from("hi"); takes_str(&owned); // &String → &str автоматически

11. Enums и Option

📖 Теория

enum — тип, который может принимать одно из нескольких значений (variants). В Rust variant'ы могут содержать данные!

12. Pattern matching

📖 Теория

match — мощный механизм сопоставления с образцом. Как switch, но гораздо мощнее: работает с любыми паттернами и типами.

  • Диапазоны: 1..=10
  • Guards: n if n > 0

  • Деструктуризация struct, tuple, массива

13. Методы и impl

15. Коллекции

📖 Теория

Коллекции — структуры для хранения множества значений. Основные в std:

  • Vec<T> — динамический массив
  • String — owned UTF-8 строка
  • HashMap<K, V> — хеш-таблица
  • HashSet<T> — множество
  • BTreeMap<K, V> — упорядоченная таблица

16. Обработка ошибок

Result, ?, panic!, anyhow, thiserror, converting errors.

📖 Теория

В Rust нет исключений. Ошибки — обычные значения типа Result<T, E>, который явно возвращается из функций.

enum Result<T, E> { Ok(T), Err(E), }

Крейты:

  • anyhow — для приложений, удобный anyhow::Result, anyhow!, bail!
  • thiserror — для библиотек, derive для кастомных ошибок
  • eyre — альтернатива anyhow с backtrace

17. Трейты (traits)

trait, impl, default методы, trait objects, dyn, associated types.

📖 Теория

Trait — «интерфейс» в Rust: набор методов, которые тип обязуется реализовать. Аналог interface в Java/Go, но с возможностью дефолтных реализаций.

trait Shape { fn area(&self) -> f64; fn perimeter(&self) -> f64; fn describe(&self) -> String { format!("Shape: area = {}, perimeter = {}", self.area(), self.perimeter()) } }

Реализация — через impl Trait for Type. Реализация неявная — нигде не надо указывать, что тип реализует trait.

Два способа использования trait:

  • Static dispatch — generics, T: Shape, мономорфизация (быстро)
  • Dynamic dispatch — &dyn Shape, Box<dyn Shape>, vtable (гибко, чуть медленнее)

Супертрейты: trait A: B — для реализации A нужно реализовать B.

Ассоциированные типы: type Item; — тип, зависящий от реализации (как в Iterator).

Встроенные трейты: Debug, Display, Clone, Copy, PartialEq, Eq, Hash, Default, From/Into, Iterator, Drop, Deref, Send, Sync.

18. Обобщения (generics)

, bounds, where, turbofish, monomorphization, trait bounds.

📖 Теория

Generics — параметризация типов. Позволяют писать один код для многих типов без дублирования.

fn largest<T: PartialOrd>(list: &[T]) -> &T { let mut largest = &list[0]; for item in list { if item > largest { largest = item; } } largest }

Где можно использовать:

  • Функции: fn foo<T>(x: T)
  • Структуры: struct Point<T> { x: T, y: T }
  • Enums: enum Result<T, E> { Ok(T), Err(E) }
  • Traits: trait Container<T>
  • Методы: impl<T> Point<T>

Trait bounds: T: Display + Clone. Через where для читаемости: fn f<T>(x: T) where T: Display.

Monomorphization: компилятор генерирует отдельный код для каждого конкретного типа. Код работает быстро (нулевая стоимость абстракции), но бинарник больше.

Turbofish: vec::<i32>::new() или parse::<f64>() — явное указание типового параметра.

19. Времена жизни (lifetimes)

'a, 'static, elision, lifetimes в struct, bounds, NLL.

📖 Теория

Lifetimes — механизм, который позволяет компилятору проверять, что ссылки валидны. Аннотации 'a — не меняют время жизни, а описывают связи между ними.

Borrow checker в большинстве случаев выводит lifetimes автоматически (lifetime elision). Аннотации нужны, когда связи неочевидны.

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { if x.len() > y.len() { x } else { y } }

Основные случаи:

  • Функции — когда есть несколько входных и возвращаемая ссылка
  • Структуры — если хранят ссылки
  • Traits — для ассоциированных типов
  • impl блоки — если методы работают со ссылками

'static — живёт всю программу. Строковые литералы — &'static str. Также T: 'static означает, что тип не содержит нестатических ссылок.

Elision rules:

  1. Каждый параметр-ссылка получает свой lifetime
  2. Если один входной — он же выходной
  3. Если несколько — но есть &self/&mut self — берётся от self

20. Замыкания (closures)

|args| body, Fn/FnMut/FnOnce, move, capture by ref/val.

📖 Теория

Замыкание — анонимная функция, которая может захватывать переменные из окружения. Синтаксис: |args| body.

let add = |a, b| a + b; let n = add(2, 3);

Три трейта замыканий:

  • Fn — не изменяет захваченное (immutable borrow)
  • FnMut — изменяет захваченное (mutable borrow)
  • FnOnce — забирает владение (можно вызвать только раз)

move — заставляет замыкание захватить переменные по значению (перенести). Нужно при передаче в поток, async-блоки, из функции.

Автоматический выбор: компилятор сам решает, какой трейт реализовать, по тому как используются переменные.

21. Итераторы

IntoIterator, Iterator, адаптеры (map, filter), потребители (collect, fold), lazy evaluation.

📖 Теория

Итератор — тип, реализующий трейт Iterator с методом next(). Итераторы ленивые: значения вычисляются по одному, по требованию.

trait Iterator { type Item; fn next(&mut self) -> Option<Self::Item>; }

Три «итераторных» трейта:

  • Iterator — даёт next(), все адаптеры
  • IntoIterator — можно использовать в for
  • FromIterator — можно collect()

Методы-адаптеры (возвращают новый итератор): map, filter, filter_map, take, skip, take_while, skip_while, chain, zip, enumerate, rev, peekable, flat_map, cycle, step_by, dedup.

Методы-потребители (завершают цепочку): collect, sum, product, count, min, max, fold, any, all, find, position, last, nth, for_each.

Создание итераторов: iter(), iter_mut(), into_iter(), vec![].iter(), 0..10, std::iter::repeat(x), std::iter::once(x).

22. Умные указатели

Box, Rc, Arc, RefCell, Mutex, Cell, Weak, выбор правильного указателя.

📖 Теория

Умные указатели — типы, которые ведут себя как указатели, но с дополнительной функциональностью. Реализуют трейты Deref и Drop.

Основные:

  • Box<T> — уникальное владение в куче. Для больших данных, рекурсивных структур, trait objects
  • Rc<T> — multiple ownership, single-threaded. Счётчик ссылок в рантайме
  • Arc<T> — как Rc, но thread-safe (atomic counter)
  • RefCell<T> — runtime borrow checking (интерьерная мутабельность)
  • Cell<T> — простой вариант RefCell для Copy-типов
  • Mutex<T>/RwLock<T> — thread-safe мутабельность
  • Weak<T> — слабая ссылка, не увеличивающая счётчик (для циклов)

Комбинации:

  • Rc<RefCell<T>> — shared mutable в одном потоке
  • Arc<Mutex<T>> — shared mutable между потоками

23. Многопоточность

thread::spawn, join, Arc, scoped threads, data races free.

📖 Теория

Rust — один из немногих языков, где data races невозможны на уровне компилятора. Всё благодаря ownership, Send и Sync трейтам.

Создание потока:

use std::thread; let handle = thread::spawn(|| { println!("from thread"); }); handle.join().unwrap(); // ждать завершения

move обязателен, если замыкание захватывает переменные — иначе поток может пережить переменную.

Обмен данными между потоками:

  • Через каналы (std::sync::mpsc) — следующий раздел
  • Через общую память: Arc<Mutex<T>>

Send и Sync:

  • Send — тип можно передать в другой поток
  • Sync — тип можно безопасно разделять между потоками (&T можно отправить)
  • Большинство типов — Send + Sync
  • Rc, RefCell — не Send/Sync
  • Arc, Mutex — Send + Sync

Scoped threads (Rust 1.63+) — потоки, которые автоматически завершаются до выхода из scope. Позволяет не использовать Arc для заимствований.

24. Каналы и Send/Sync

mpsc, sync/async каналы, crossbeam, Send и Sync подробнее.

📖 Теория

Каналы — способ передавать данные между потоками без разделяемой памяти. «Do not communicate by sharing memory; instead, share memory by communicating».

mpsc (Multi-Producer, Single-Consumer) — встроенный канал std. Несколько отправителей, один получатель.

use std::sync::mpsc; let (tx, rx) = mpsc::channel(); thread::spawn(move || { tx.send(42).unwrap(); }); let value = rx.recv().unwrap(); // 42

Типы каналов:

  • mpsc::channel() — unbounded (без ограничения)
  • mpsc::sync_channel(n) — bounded (sync, блокирующий)
  • crossbeam-channel — MPMC (multi-producer multi-consumer), быстрее и гибче
  • tokio::sync::mpsc — асинхронный канал

Методы:

  • send(v) — блокирующая отправка (или ошибка если приёмник упал)
  • recv() — блокирующее получение
  • try_recv() — неблокирующее, возвращает Result
  • iter() — итератор по сообщениям
  • clone() на sender — несколько отправителей

Send и Sync: тип Send, если его можно передать в другой поток. Sync — если &T можно передать в другой поток (безопасно разделять ссылки).

25. Async/await и Tokio

async fn, .await, futures, Tokio runtime, tokio::spawn, tokio::main.

📖 Теория

Async/await в Rust — синтаксис для асинхронных функций. async fn возвращает Future, который нужно запустить через executor (обычно Tokio).

async fn fetch_data() -> String { "data".to_string() } // Использование let data = fetch_data().await;

Future — ленивый: ничего не делает, пока не будет опрошен executor'ом (.await или spawn).

Tokio — доминирующий асинхронный runtime:

  • #[tokio::main] — макрос, разворачивает main в runtime
  • tokio::spawn — запуск задачи в фоне
  • tokio::join! — ждать несколько futures параллельно
  • tokio::select! — гонка между futures
  • tokio::time::sleep — async sleep

Экосистема: reqwest (HTTP), sqlx (SQL), axum/actix (web), tonic (gRPC), async-std (альтернатива).

Ключевое отличие от потоков: асинхронные задачи очень дешёвые (сотни байт против мегабайт). Один поток может обрабатывать тысячи задач.

27. Unsafe Rust

unsafe блок, raw pointers, FFI, when to use, memory safety.

📖 Теория

unsafe — позволяет делать операции, которые компилятор не может проверить. Не «отключает» borrow checker полностью, а открывает 5 суперспособностей:

  1. Разыменование raw указателей (*const T, *mut T)
  2. Вызов unsafe-функций (включая extern "C")
  3. Доступ к изменяемым static переменным
  4. Реализация unsafe трейтов (Send/Sync вручную)
  5. Доступ к полям union

Зачем:

  • FFI с C/C++/OS API
  • Низкоуровневые структуры данных (Vec, HashMap внутри)
  • Оптимизация горячих путей
  • Специфичные платформы, embedded

Правила:

  • unsafe блок должен быть минимальным
  • Всегда объясняйте в комментарии, почему безопасно (safety comment)
  • Оборачивайте в безопасный API (soundness)
  • Тестируйте под Miri (интерпретатор UB)

Undefined Behavior (UB): data race, dangling pointer, разыменование null, нарушение alignment, race conditions — всё, что unsafe может допустить.

29. Производительность

Benchmarking, profiling, zero-cost abstractions, оптимизация, LTO, PGO.

📖 Теория

Rust — быстрый язык. Но оптимизация требует измерений, а не догадок.

Инструменты:

  • criterion — бенчмарки с статистикой
  • perf (Linux), DTrace (macOS) — системное профилирование
  • flamegraph — визуализация flame graph
  • cargo flamegraph — обёртка
  • valgrind/callgrind — детальный анализ
  • tokio-console — async-профилирование

Zero-cost abstractions — итераторы, замыкания, generic'и компилируются в тот же код, что ручные циклы.

Правила оптимизации:

  1. Сначала измерь (профилируй)
  2. Оптимизируй горячие пути
  3. Избегай аллокаций в цикле
  4. Используй with_capacity
  5. String vs &str, Vec vs slice
  6. LTO, codegen-units=1, opt-level=3
  7. PGO — Profile-Guided Optimization
