01. Введение в Bash

История, POSIX, GNU, чем Bash отличается от sh и zsh, где применяется.

📖 Что такое Bash

Bash — это командная оболочка (shell) и одновременно язык программирования. Слово «shell» означает «оболочка» — программа, которая оборачивает ядро ОС и предоставляет удобный интерфейс для запуска команд.

Bash умеет:

  • Читать команды и передавать их ядру ОС для выполнения
  • Хранить состояние между командами (переменные, функции, текущая директория)
  • Управлять вводом/выводом (перенаправления, pipes)
  • Программировать: циклы, условия, массивы, функции
  • Работать с заданиями (jobs): фон, приостановка, приоритеты

Создан Брайаном Фоксом в 1989 году для проекта GNU. Название — игра слов: Bourne Again SHell (снова Bourne shell, потому что основа — это sh Стивена Борна).

📅 История shell

1971 Thompson shell — первая Unix-оболочка
1979 Bourne shell (sh) — Стивен Борн создал стандарт
1978 C shell (csh) — Билл Джой, с C-подобным синтаксисом
1983 KornShell (ksh) — Дэвид Корн
1989 Bash 0.99 — первый релиз Брайана Фокса
1990 zsh — появился как мощная альтернатива (популярен сейчас)
2019 macOS Catalina переходит на zsh по умолчанию (Bash 3.2 устарел по лицензии)
2024 Bash 5.2 — актуальная версия

💡 Интересные факты

  • Имя «Bash» — акроним Bourne Again SHell. Это каламбур, ссылающийся на перерождение (born again).
  • Bash 3.2 (2007) до сих пор стоит в macOS, потому что переход на Bash 4+ требует GPLv3, а Apple не любит GPLv3 в системных компонентах.

🧩 Дополнение: Границы Bash и переносимость

Bash особенно удобен, когда нужно связать системные утилиты, файлы и процессы. Но его расширения не являются универсальным синтаксисом для всех оболочек, поэтому требования к переносимости стоит определить до написания кода.

Практические ориентиры:

  • Уточните, где будет исполняться скрипт: локально, в CI или в минимальном контейнере.
  • Для переносимого сценария избегайте bash-специфичных массивов и [[ ]] либо явно указывайте Bash в shebang.
  • Проверьте оболочку, а не только наличие команды bash.

Небольшой пример: адаптируйте его для безопасного тестового каталога.

printf 'Bash version: %s\n' "$BASH_VERSION"

Самопроверка. Убедитесь, что команда работает в целевой оболочке и версии системы.

02. Терминал и установка

Как открыть, настроить, .bashrc, .bash_profile, PATH, история.

📖 Терминал vs Shell

Терминал — программа, которая эмулирует физический терминал. Окно с текстом. Примеры: GNOME Terminal, iTerm2, Windows Terminal, Alacritty, Kitty.

Shell — программа, которая работает внутри терминала и интерпретирует ваши команды. Примеры: bash, zsh, fish.

Один терминал → один или несколько shell → много процессов.

Prompt — приглашение ко вводу. Стандартно выглядит как user@host:~$:

  • user — текущий пользователь
  • host — имя машины
  • ~ — текущая директория (домашняя)
  • $ — обычный пользователь; # — root

📖 Конфигурационные файлы

ФайлКогда читается

~/.bash_profileLogin-сессии (SSH, терминал)

Правило: PATH и переменные окружения обычно в .bash_profile, алиасы и prompt — в .bashrc. Многие делают так: .bash_profile содержит source ~/.bashrc.

🧩 Дополнение: Диагностика терминальной среды

Поведение команд может отличаться из-за PATH, алиасов и настроек запуска оболочки. Если команда ведёт себя неожиданно, сначала выясните, какой исполняемый файл или функция фактически вызывается.

Практические ориентиры:

  • Используйте type -a имя_команды, чтобы увидеть все найденные варианты.
  • Проверьте PATH по элементам и убедитесь, что личные каталоги не перекрывают системные утилиты.
  • Не добавляйте случайные каталоги в PATH без проверки их содержимого.

Небольшой пример: адаптируйте его для безопасного тестового каталога.

printf '%s\n' "$PATH" | tr ':' '\n'

Самопроверка. Повторите проверку с пустым значением и с данными, содержащими пробелы.

03. Первый скрипт

shebang, chmod, запуск, комментарии, простые команды.

📖 Что такое скрипт

Скрипт — файл с командами для shell. Строки исполняются сверху вниз, как если бы вы вводили их вручную.

Минимальный скрипт:

  1. Первая строка — shebang: #!/usr/bin/env bash говорит ОС, какой интерпретатор использовать.
  2. Остальное — команды, каждая с новой строки.
  3. Сохранить как script.sh.
  4. Дать право на исполнение: chmod +x script.sh.
  5. Запустить: ./script.sh.

📖 Shebang: что и зачем

Shebang (#!) — магический комментарий, который сообщает ядру, каким интерпретатором запускать файл.

ShebangЧто означает
#!/bin/bashАбсолютный путь к Bash
#!/usr/bin/env bashНайти bash в PATH (переносимо)
#!/bin/shPOSIX shell (может быть dash)
#!/usr/bin/python3Python-скрипт

Рекомендация: #!/usr/bin/env bash — работает в любой системе, где bash в PATH.

🎮 Интерактив: конструктор скрипта

$ ./hello.sh Привет, мир!

📐 Пример

🧩 Дополнение: Надёжный запуск скрипта

Успешный запуск зависит не только от текста файла: важны права доступа, окончания строк, интерпретатор и текущая директория. Проверяйте сценарий тем же способом, каким его будет запускать пользователь или планировщик.

Практические ориентиры:

  • Сначала запустите bash -n script.sh для проверки синтаксиса.

04. Переменные и окружение

VAR=value, $VAR, ${VAR}, export, env, readonly, переменные по умолчанию.

📖 Теория

Переменная — именованное хранилище значения в памяти shell. В Bash переменные создаются просто присваиванием:

NAME="значение"

⚠️ Без пробелов вокруг = — иначе Bash попытается выполнить NAME как команду.

Использование: $NAME или ${NAME}. Скобки нужны, если имя склеивается с текстом: ${NAME}_suffix.

Типы переменных:

  • Локальные — только в текущем shell
  • Environment (окружение) — экспортируются в дочерние процессы через export
  • Readonly — только для чтения, нельзя изменить

🎮 Интерактив: раскрытие переменных

Значение $USER = alice

📐 Примеры

08. case и pattern matching

📖 Теория

24. Exit codes

📖 Теория

Каждая команда возвращает exit code — целое число 0–255. 0 — успех, любое другое — ошибка.

Проверка: $? — код последней команды.

Операторы:

  • cmd1 && cmd2 — cmd2 только если cmd1 успешна
  • cmd1 || cmd2 — cmd2 только если cmd1 упала

25. set -euo pipefail

📖 Строгий режим

set -euo pipefail — золотой стандарт в начале каждого продакшн-скрипта.

  • -e (errexit) — выходить при любой ошибке

  • -x — печатать команды перед выполнением (для отладки)
  • -E — наследовать ERR trap в функциях

📖 Теория

Bash медленный по сравнению с Python/Go, но в скриптах можно сильно ускориться:

  • Встроенные команды (builtin) быстрее внешних — нет fork

  • Одна команда вместо цикла: awk/sed справятся лучше
  • Массивы вместо файлов для небольших данных
  • Параллелизм — xargs -P, background + wait
  • Не запускать grep | grep | grep — один awk быстрее

🧩 Дополнение: Инженерная ответственность Lead/DevOps

На старшем уровне важны не только корректные команды, но и эксплуатационные свойства: наблюдаемость, безопасное повторное выполнение, понятные ошибки, документация и владение изменениями. Скрипт должен быть поддерживаемым другим человеком.

Практические ориентиры:

  • Определите владельца, входы, выходы и последствия повторного запуска.
  • Добавьте тесты на успешный сценарий, неверный ввод и частичный отказ.
  • Секреты храните в системе управления секретами, а не в репозитории.

Небольшой пример: адаптируйте его для безопасного тестового каталога.

Перед внедрением подготовьте план отката и критерии успешности.
