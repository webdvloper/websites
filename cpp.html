01. Введение в C++

История, философия, применение, стандарты языка, экосистема.

📖 Что такое C++

C++ — компилируемый, статически типизированный, мультипарадигменный язык программирования. Создан Бьёрном Страуструпом (датский учёный) в 1979-1983 годах в Bell Labs. Изначально назывался «C с классами», переименован в C++ в 1983 году (оператор ++ — инкремент).

Ключевые особенности:

  • Ручное управление памятью — нет GC, полный контроль
  • Zero-cost abstractions — высокоуровневый код, низкоуровневая производительность
  • RAII — идиома управления ресурсами через конструкторы/деструкторы
  • Шаблоны — обобщённое программирование (compile-time)
  • STL — стандартная библиотека шаблонов (контейнеры, алгоритмы, итераторы)
  • Мультипарадигма — ООП, процедурный, функциональный, generic
  • Совместимость с C — можно компилировать C-код

Применение: игры (Unreal, Unity engine), HFT (высокочастотный трейдинг), ОС (Windows, Linux, macOS), браузеры (Chrome, Firefox), embedded, ML (TensorFlow, PyTorch), БД (MySQL, MongoDB), компиляторы (LLVM, Clang).

03. Переменные и типы данных

Встроенные типы, auto, const, constexpr, typedef, using, size_t.

📖 Теория

C++ — статически типизированный язык. У каждой переменной есть тип, известный на этапе компиляции.

Встроенные типы:

  • bool — true/false (1 байт, но sizeof может быть 1)
  • char — символ (1 байт)
  • int — целое (обычно 4 байта)
  • short, long, long long — целые разного размера
  • float (4 байта), double (8 байт) — с плавающей точкой
  • size_t — беззнаковый для размеров (результат sizeof)
  • void — «пустота» (нет значения)
  • auto (C++11) — вывод типа компилятором

Модификаторы: signed/unsigned, short/long. Квалификаторы: const, constexpr, volatile, mutable, static.

Опасности: непредсказуемые размеры (int может быть 2 или 4 байта), переполнения (undefined behavior для signed), неинициализированные переменные.

04. Операторы и выражения

Арифметические, сравнения, логические, битовые, инкремент/декремент.

📖 Теория

Арифметические: + - * / %. Инкремент/декремент: ++ -- (префиксные и постфиксные).

Сравнения: == != < > <= >=. Возвращают bool.

Логические: && || !. Короткое замыкание.

Битовые: & | ^ ~ << >>.

Присваивание: = += -= *= /= %= &= |= ^= <<= >>=. Возвращает ссылку на левый операнд, поддерживает цепочки a = b = c.

Тернарный: cond ? a : b.

Особенности:

  • В C++ можно перегружать операторы (кроме :: . .* ?:)
  • Операторы имеют приоритет (скобки — лучший друг)
  • Порядок вычислений операндов часто не определён
  • Правило: не изменяйте одну переменную несколько раз в одном выражении

05. Условия и switch

if/else, switch, тернарный, if constexpr (C++17), switch с инициализацией (C++17).

📖 Теория

if/else — стандартное ветвление. Условие — bool или неявно приводимое к bool (0 = false, остальное = true).

switch — сравнение с целочисленными константами. Важно: без break происходит fall-through!

switch (value) { case 1: case 2: // для 1 и 2 break; case 3: // только для 3 break; default: // остальное break; }

Новинки:

  • if constexpr (C++17) — compile-time ветвление в шаблонах
  • switch с инициализацией (C++17): switch (int x = f(); x) { ... }
  • [[fallthrough]] (C++17) — явно указать намеренный fall-through

Правила: никогда не забывайте break; используйте default; brace-инициализация { } рекомендуется; избегайте глубоких вложенных условий.

06. Циклы

for, while, do-while, range-based for, break/continue, goto.

📖 Теория

Четыре вида циклов:

  • for — классический, с инициализацией/условием/шагом
  • range-based for (C++11) — по контейнерам
  • while — пока условие
  • do-while — хотя бы раз
for (int i = 0; i < 10; ++i) { } for (auto& item : container) { } while (condition) { } do { } while (condition);

break — выход, continue — следующая итерация. goto — редко, но иногда нужен (выход из вложенных циклов).

Важно: используйте ++i вместо i++ для итераторов (хотя для int компилятор всё равно оптимизирует). Для объектов без оптимизации i++ создаёт копию.

Range-based for (C++11) — самый читаемый способ:

  • for (auto x : v) — копия каждого элемента
  • for (auto& x : v) — ссылка (можно изменять)
  • for (const auto& x : v) — const-ссылка (рекомендуется)

07. Массивы

C-массивы, std::array, std::vector, multidimensional arrays.

📖 Теория

Три вида массивов в C++:

  • C-массивы — int arr[10], размер фиксирован, размер в байтах через sizeof
  • std::array<T, N> (C++11) — обёртка над C-массивом, знает свой размер, range-based for
  • std::vector<T> — динамический массив, расширяется автоматически

C-массивы — наследие C, легко «стреляют в ногу»:

  • Не знают своего размера (передаются в функцию как указатель)
  • Не проверяют границы — выход за пределы UB
  • Не копируются при присваивании (нужен memcpy)

std::array — тот же C-массив, но безопаснее и удобнее:

  • Знает размер: .size()

📖 Теория

Функция — именованный блок кода, принимающий параметры и возвращающий результат.

Способы передачи параметров:

  • По значению: int x — копия
  • По ссылке: int& x — можно изменить
  • По const-ссылке: const int& x — без копирования, только для чтения

int max(int a, int b); double max(double a, double b); int max(int a, int b, int c);

10. Указатели и ссылки

*, &, nullptr, арифметика указателей, ссылки vs указатели, const.

📖 Теория

Указатель — переменная, хранящая адрес другой переменной. Тип: T*.

int x = 42; int* p = &x; // p хранит адрес x std::cout << *p; // разыменование = 42 *p = 100; // изменение x через указатель

Ссылка (C++ стиль) — псевдоним для существующей переменной. Не может быть null, должна быть инициализирована.

int x = 42; int& ref = x; // ref — псевдоним x ref = 100; // изменение x

Различия:

  • Указатель: может быть nullptr, может менять цель, есть арифметика
  • Ссылка: всегда привязана к объекту, не может быть null, не может менять цель

const в контексте указателей:

  • const T* p — указатель на константу (нельзя менять *p)
  • T* const p — константный указатель (нельзя менять сам p)
  • const T* const p — оба

nullptr (C++11) — типизированный null-указатель. Лучше, чем NULL или 0.

12. Конструкторы и деструкторы

Конструктор, деструктор, copy/move конструкторы, Rule of 0/3/5.

📖 Теория

Конструктор — специальный метод, вызываемый при создании объекта. Имя = имя класса. Нет возвращаемого типа.

Деструктор — вызывается при удалении объекта. Имя = ~ClassName. Освобождает ресурсы.

class Resource { public: Resource() { std::cout << "Created"; } ~Resource() { std::cout << "Destroyed"; } };

Типы конструкторов:

  • Default — без параметров
  • Parameterized — с параметрами
  • Copy constructor — T(const T&)
  • Move constructor — T(T&&) (C++11)
  • Delegating — вызывает другой конструктор (C++11)
  • Explicit — запрет неявных преобразований

Rule of 0/3/5:

  • Rule of 0: не определяйте деструктор, копирование, move — пусть компилятор делает всё
  • Rule of 3 (C++98): если определили деструктор, copy ctor или copy assignment — определите все три
  • Rule of 5 (C++11): добавьте move ctor и move assignment

13. Наследование

public, protected, private наследование, base, порядок вызова.

📖 Теория

Наследование — создание нового класса на основе существующего. Дочерний класс получает члены родителя.

class Animal { public: void eat() { std::cout << "eating"; } }; class Dog : public Animal { public: void bark() { std::cout << "woof"; } };

Виды наследования:

  • public — public → public, protected → protected (обычное «is-a»)
  • protected — public → protected (редко используется)
  • private — public → private (has-a через наследование, редко)

Что не наследуется: конструкторы, деструкторы, operator=, friend-функции.

Порядок вызова: сначала базовые классы (сверху вниз), потом члены (по порядку объявления), потом тело конструктора.

Множественное наследование — можно, но осторожно (ромбовидное наследование → виртуальное наследование).

virtual, override, final, vtable, полиморфизм, RTTI.

📖 Теория

Виртуальная функция — метод, который может быть переопределён в наследнике. Обеспечивает динамический полиморфизм — вызов через указатель/ссылку на базовый класс вызывает правильную реализацию.

class Animal { public: virtual void speak() { std::cout << "..."; } virtual ~Animal() = default; // ВАЖНО! }; class Dog : public Animal { public: void speak() override { std::cout << "Woof"; } };

Как работает: компилятор создаёт vtable — таблицу указателей на виртуальные функции для каждого класса. Каждый объект содержит vptr — указатель на vtable. При вызове виртуальной функции — двойное разыменование (vptr → функция).

Правила:

  • virtual в базовом классе
  • override (C++11) в наследнике — явно указываем, что переопределяем
  • final — запрет дальнейшего переопределения
  • Виртуальный деструктор обязателен для полиморфного удаления
  • Виртуальные функции нельзя вызывать из конструктора/деструктора безопасно

15. Абстрактные классы

Pure virtual, интерфейсы, multiple inheritance, interface segregation.

📖 Теория

Абстрактный класс — класс, содержащий хотя бы одну pure virtual функцию (= 0). Нельзя создать экземпляр. Предназначен для наследования.

class Shape { public: virtual double area() const = 0; // pure virtual virtual ~Shape() = default; }; // Shape s; // ❌ ошибка — абстрактный Circle c(5); // ✅ OK — реализует area()

Интерфейс в C++ — это абстрактный класс, у которого все методы pure virtual и нет данных. Аналог interface в Java/C#.

class IDrawable { public: virtual void draw() = 0; virtual ~IDrawable() = default; };

Множественное наследование интерфейсов — обычная практика. Класс может реализовать много интерфейсов.

Pure virtual destructor — можно объявить pure, но нужно определить (для правильного разрушения):

class Base { public: virtual ~Base() = 0; // pure }; Base::~Base() = default; // обязательно

16. Перегрузка операторов

operator+, operator==, operator<<, operator(), правила, ограничения.

📖 Теория

Перегрузка операторов — возможность определить своё поведение для операторов при работе с пользовательскими типами. Позволяет писать: a + b, a == b, std::cout << a.

class Complex { double re, im; public: Complex(double r, double i) : re(r), im(i) { } Complex operator+(const Complex& other) const { return Complex(re + other.re, im + other.im); } bool operator==(const Complex& other) const { return re == other.re && im == other.im; } };

Нельзя перегрузить: ::, ., .*, ?:, sizeof, typeid, alignof.

Правила:

  • Хотя бы один операнд — пользовательский тип
  • Нельзя менять приоритет/ассоциативность
  • Нельзя создавать новые операторы
  • Не перегружайте интуитивно непонятные операторы

Важные операторы:

  • operator= — копирование (Rule of 3/5)
  • operator==, operator< — сравнение
  • operator+, operator- — арифметика
  • operator<<, operator>> — потоки
  • operator() — функтор
  • operator[] — индексация
  • operator-> — умные указатели
  • operator++ — инкремент

17. Шаблоны (templates)

template<typename T>, specialization, variadic, concepts (C++20).

📖 Теория

Шаблоны — механизм обобщённого программирования на этапе компиляции. Компилятор генерирует отдельный код для каждого типа (monomorphization).

template<typename T> T max(T a, T b) { return a > b ? a : b; } max(3, 5); // max<int> max(3.14, 2.71); // max<double> max<int>(3, 5); // явное указание

Виды шаблонов:

  • Function templates — обобщённые функции
  • Class templates — обобщённые классы
  • Variable templates (C++14) — обобщённые переменные
  • Alias templates (C++11) — обобщённые псевдонимы
  • Variadic templates (C++11) — переменное число параметров
  • Concepts (C++20) — ограничения на типы

Плюсы: zero-cost abstractions, type safety, производительность.

Минусы: медленная компиляция, раздувание бинарника, сложные ошибки.

18. STL: контейнеры

vector, list, map, unordered_map, set, deque, stack, queue, priority_queue.

📖 Теория

STL (Standard Template Library) — часть стандартной библиотеки C++. Контейнеры делятся на три категории:

  • Последовательные: vector, array, deque, list, forward_list
  • Ассоциативные: set, map, multiset, multimap (на основе деревьев, O(log n))
  • Неупорядоченные: unordered_set, unordered_map (на основе хеш-таблиц, O(1) в среднем)
  • Адаптеры: stack, queue, priority_queue

Основные контейнеры:

std::vector<int> v = {1, 2, 3}; std::list<int> lst = {1, 2, 3}; std::map<std::string, int> m = {{"a", 1}}; std::unordered_map<std::string, int> um; std::set<int> s = {1, 2, 3}; std::deque<int> dq = {1, 2, 3};

Когда что использовать:

  • vector — по умолчанию, для 90% случаев
  • map — когда нужен отсортированный ключ-значение
  • unordered_map — когда важен быстрый доступ (не порядок)
  • set — уникальные отсортированные элементы
  • deque — быстрая вставка/удаление в начало и конец
  • list — частая вставка/удаление в середину

20. Итераторы и ranges

Категории итераторов, begin/end, reverse, insert, stream iterators, ranges.

📖 Теория

Итератор — объект, позволяющий обходить контейнер. Абстракция над указателем, но более гибкая.

Категории итераторов (по возрастанию возможностей):

  • Input — однопроходный, для чтения
  • Output — однопроходный, для записи
  • Forward — многопроходный вперёд
  • Bidirectional — вперёд и назад
  • Random Access — прыжки на любое расстояние (vector, array, deque)
  • Contiguous (C++20) — непрерывная память

Основные итераторы: begin/end, cbegin/cend, rbegin/rend, crbegin/crend, advance, next, prev, distance.

Специальные:

  • inserter — вставляет через .insert()
  • back_inserter — через .push_back()

21. Умные указатели

unique_ptr, shared_ptr, weak_ptr, make_unique, make_shared.

📖 Теория

Умные указатели — классы, автоматически управляющие памятью. Заменяют new/delete.

Виды:

  • unique_ptr<T> — эксклюзивное владение, не копируется, только перемещается
  • shared_ptr<T> — разделяемое владение, счётчик ссылок (атомарный), освобождает когда счётчик = 0
  • weak_ptr<T> — слабая ссылка, не увеличивает счётчик (для разрыва циклов)

Создание:

auto p1 = std::make_unique<int>(42); auto p2 = std::make_shared<int>(42);

Правила:

  • По умолчанию — unique_ptr
  • Только когда действительно нужно разделение — shared_ptr
  • Не используйте new напрямую — используйте make_unique/make_shared
  • Избегайте циклов с shared_ptr — используйте weak_ptr для «обратных» ссылок

22. Исключения

try/catch/throw, типы исключений, noexcept, stack unwinding.

📖 Теория

Исключения — механизм обработки ошибок. При throw стек разворачивается (stack unwinding), вызываются деструкторы локальных объектов, потом управление переходит в catch.

try { throw std::runtime_error("error"); } catch (const std::exception& e) { std::cout << e.what(); }

Иерархия std::exception:

  • logic_error — invalid_argument, out_of_range, length_error
  • runtime_error — range_error, overflow_error, system_error
  • bad_alloc — не удалось выделить память
  • bad_cast — неудачный dynamic_cast
  • bad_typeid — typeid с nullptr

Правила:

  • Ловите по const-ссылке (catch (const std::exception& e))
  • Не глотайте исключения (пустой catch)
  • Не используйте исключения для управления потоком
  • Помечайте noexcept функции, которые не бросают (move, destructor)
  • RAII — деструкторы должны быть noexcept

noexcept — обещание компилятору, что функция не бросает. Если бросит — std::terminate.

23. RAII и управление ресурсами

RAII idiom, resource acquisition is initialization, деструкторы, scope guard.

📖 Теория

RAII (Resource Acquisition Is Initialization) — ключевая идиома C++. Ресурс захватывается в конструкторе и освобождается в деструкторе. Жизнь ресурса = жизнь объекта.

class File { FILE* f; public: File(const char* path) { f = std::fopen(path, "r"); if (!f) throw std::runtime_error("open failed"); } ~File() { if (f) std::fclose(f); } // автоматически };

Что даёт RAII:

  • Автоматическое освобождение — не нужно помнить про delete/close
  • Exception safety — ресурс освобождается даже при исключении
  • Нет утечек — даже при return или throw
  • Читаемость — намерения выражены в типе

Что оборачивается через RAII:

  • Память → unique_ptr, shared_ptr
  • Файлы → std::fstream, собственные обёртки
  • Мьютексы → std::lock_guard, std::unique_lock
  • Соединения БД → RAII-обёртки
  • Сокеты → RAII-обёртки
  • Любые ресурсы, которые нужно освобождать

Правило нуля: если все ресурсы обёрнуты в RAII, ваш класс не должен объявлять деструктор, copy, move — компилятор сделает правильно.

24. Move-семантика

lvalue/rvalue, std::move, move constructor, rvalue reference, perfect forwarding.

📖 Теория

Move-семантика (C++11) — механизм перемещения ресурсов из одного объекта в другой без копирования. Основа производительности современного C++.

lvalue / rvalue:

  • lvalue — у объекта есть имя/адрес: x, arr[0], *p
  • rvalue — временный объект: 5, x + y, func()

Ссылки:

  • T& — lvalue reference (только на lvalue)
  • T&& — rvalue reference (на rvalue) — C++11

std::move — не перемещает, а приводит к rvalue-ссылке. Говорит «можешь забрать ресурсы».

std::string s1 = "hello"; std::string s2 = std::move(s1); // перемещение // s1 теперь в неопределённом, но валидном состоянии

Move-конструктор и move-присваивание:

class Buffer { int* data; size_t size; public: Buffer(Buffer&& other) noexcept : data(other.data), size(other.size) { other.data = nullptr; other.size = 0; } };

Правила:

  • move-конструктор должен быть noexcept — иначе vector не будет его использовать
  • После move объект должен быть в валидном (но неопределённом) состоянии
  • Не используйте moved-from объект (кроме деструктора/присваивания)
  • Правило нуля: не пишите move вручную — используйте RAII-обёртки

25. Лямбды и замыкания

[capture](params) -> ret { body }, захват по значению/ссылке, mutable.

📖 Теория

Лямбда-выражение (C++11) — анонимная функция, определённая прямо в месте использования. Синтаксис:

[capture](params) -> return_type { body }

Захват (capture) — способ доступа к переменным извне:

  • [] — ничего не захватывает
  • [=] — по значению (копия)
  • [&] — по ссылке
  • [x, &y] — x по значению, y по ссылке
  • [=, &x] — все по значению, кроме x
  • [&, x] — все по ссылке, кроме x
  • [this] — захват this (для методов класса)

mutable — позволяет изменять захваченные по значению переменные внутри лямбды.

int x = 5; auto f = [x]() mutable { x++; return x; }; f(); // x внутри = 6 // x снаружи по-прежнему 5 (захвачен по значению)

Опасности: захват по ссылке в долгоживущих лямбдах (например, в потоках) — UB, если объект умрёт раньше лямбды.

Лямбды — это функторы: компилятор генерирует класс с operator(). Размер зависит от захваченных переменных.

  • std::async, std::future — асинхронность

Проблемы:

  • Data race — одновременный доступ к памяти без синхронизации → UB
  • Deadlock — взаимная блокировка
  • Race condition — результат зависит от порядка

Правила:

  • Всегда используйте RAII (lock_guard, unique_lock)
  • Минимизируйте время под мьютексом
  • Для простых случаев — atomic вместо mutex (быстрее)
  • Захватывайте мьютексы в одном порядке (избежать deadlock)
  • Не блокируйте надолго

27. Асинхронность и future

std::async, std::future, std::promise, packaged_task, coroutines.

📖 Теория

Высокоуровневые инструменты асинхронности в C++11:

  • std::async — запустить задачу асинхронно
  • std::future<T> — «обещание» результата в будущем
  • std::promise<T> — установить значение для future
  • std::packaged_task — обернуть callable в future
  • std::shared_future — future, который можно копировать

std::async:

auto fut = std::async(std::launch::async, []() { return heavyCompute(); }); int result = fut.get(); // блокирует до готовности

Launches:

  • std::launch::async — обязательно в новом потоке
  • std::launch::deferred — отложенно, при вызове get()
  • async | deferred (по умолчанию) — на усмотрение реализации

Coroutines (C++20) — новый способ асинхронности, без потоков. Основа современных async-библиотек (asio, cppcoro).

Внимание: если future из async не дождаться — деструктор заблокирует! Всегда join/get.

29. Оптимизация и производительность

Профилирование, inline, branch prediction, cache, SIMD, компиляторы.

📖 Теория

C++ — быстрый язык, но не «магически». Оптимизация требует измерений и понимания архитектуры.

Основные принципы:

  • Measure first — сначала измерить, потом оптимизировать
  • Алгоритмическая оптимизация — O(n log n) vs O(n²) важнее констант
  • Кэш-эффективность — data locality критична
  • Избегать аллокаций — в горячем пути
  • Профилирование — perf, VTune, gprof

Компилятор:

  • -O0 — без оптимизации (для отладки)
  • -O1 — базовая
  • -O2 — стандартная
  • -O3 — агрессивная (векторизация, разворачивание)
  • -Ofast — с нарушением стандарта
  • -march=native — под текущий CPU
  • -flto — Link Time Optimization

Профилировщики: perf (Linux), VTune (Intel), gprof, Valgrind (callgrind), Google Performance Tools.
